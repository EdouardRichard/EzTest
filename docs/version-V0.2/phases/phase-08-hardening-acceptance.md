# Phase P8 — 硬化与验收

> 阶段计划，不是任务计划。会话启动使用 [implementation-phase-plan.md](../implementation-phase-plan.md) 顶部提示词；PHASE_ID=P8；PHASE_FILE=phase-08-hardening-acceptance.md；PREV_HANDOFF=phase-07-handoff.md。

## 目标

把 0.2 从“功能齐”推到“可交付”：全量 E2E、真实 LLM、多 SUT、长上下文、多副本、P9、SLO/安全/打包/文档、缺陷修复。

## 输入

- 全部设计/契约/handoff
- P7 handoff
- 0.1 能力矩阵（capability-matrix）
- 用户验收标准/真实环境

## 范围（In）

- 全量旅程 E2E：管理员配置→版本（多 SUT/页面/API/库/账号/代码仓）→澄清→设计→确认→执行→问题/报告→链路→收尾→重开。
- 真实 LLM 验收；多 SUT/跨系统；长会话/长执行/上下文压缩；多副本故障/滚动升级。
- P9 五项验收；SLO；打包/部署；文档同步。
- 0.1 P0–P8 能力矩阵逐项签字；缺陷修复；风险清单。

## 不在范围（Out）

- 0.3 新能力。
- 绕过验收的“临时降级”；如必须降级，记录为已知限制并让用户批准。

## 交付物

- 验收报告/证据；SLO/性能结果；安全审计；打包/部署说明；能力矩阵签字。
- 缺陷修复与回归；`phase-08-handoff.md` / 最终交付说明。

## 依赖与前置

- P7 完成；所有 contracts frozen；所有阶段 handoff 可读。
- 真实环境（LLM/executor/多副本/共享存储）可用。

## 验收/演示

1. 全量旅程在真实 LLM/真实浏览器/多 SUT 下跑通。
2. 长上下文/长执行无 context_overflow 终态失败；恢复/压缩可查。
3. 多副本/滚动升级/故障恢复不重复执行、不批量中断。
4. P9/P0–P8 能力矩阵全绿；无 P0/P1 缺陷。
5. 用户验收通过。

## Handoff 必须包含

- 最终验收清单/证据索引；已知限制；0.3 backlog；运行/部署手册入口。

## 风险/约束

- 不要在 P8 新增大功能；只做修复/硬化/验收。
- 任何降级必须显式记录并获用户批准。
- 验收证据必须可复现（命令/环境/数据/截图）。
