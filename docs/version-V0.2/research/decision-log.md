## 2. 版本生命周期

| # | 决策 | 来源 |
|---|---|---|
| D05 | 版本状态只是**对外投影**：`initial / running / completed`，不是功能门禁；Agent 不读 version.status。 | [用户] |
| D06 | 版本由**收尾 Agent** 通过结构化 `version.close` 关闭；新增目标（需求、用例确认、复测等）自动使完成标记失效，回到 running。 | [用户] |
| D07 | 完成口径 = **过程闭环**：无开放工作项、无运行中任务、所有需求已闭环或 obsolete、报告已发布；用例失败/未修问题不阻断。 | [用户] |
| D08 | 需求闭环由 Agent 结构化 `requirement.goal_met` + 服务端校验（覆盖 + 执行结果）产生；需求/用例新增或变更可使闭环失效。 | [推导] |

## 3. 资源、权限与信任模型

| # | 决策 | 来源 |
|---|---|---|
| D09 | 管理员配置：用户、SUT（名称/简介/主页/环境入口）、目标数据库、测试账号、LLM、系统设置、全局知识。登录用户可新增代码仓、版本，执行澄清/设计/执行/问题/报告。 | [用户] |
| D10 | 一个版本可绑定**多个 SUT**；每个 SUT 绑定选择环境/入口、目标库、测试账号、代码仓；版本→资源为多对多/一对多。 | [用户] |
| D11 | 测试账号密码**允许 AI 读取使用**；面向开发/测试环境的信任模型，不做密钥托管/加密/复杂安全加固；UI 不回显、操作审计。 | [用户] |
| D12 | 跨系统用例：一条用例可包含多个步骤，**步骤级指定目标 SUT**；执行器为一个用例管理多个 SUT 的浏览器上下文/Session。 | [用户] |
| D13 | 波次仍为**同版本单活跃波**；跨系统用例作为一个整体调度，按 SUT 做并发/资源限制。 | [推导] |
| D13a | **SUT 页面清单**：一个 SUT 有多条前端页面链接（名称/URL/路由/说明/登录角色/模块），按环境区分；管理员维护，AI 探索可提议新增，需确认后入库；版本绑定 SUT 时选择页面范围；用例/场景指定入口页面，步骤可在页面间导航；跨系统步骤目标 = SUT + 环境 + 页面/URL。 | [用户] |

## 4. 需求与澄清

| # | 决策 | 来源 |
|---|---|---|
| D14 | 需求 = 逻辑对象 + **不可变版本**；状态 `draft / clarified / closed / obsolete`；确认即冻结当前版本。 | [用户] |
| D15 | 已澄清需求再编辑或 AI 回退 → 生成新 draft 版本、写原因、关联用例标 stale/needs_revalidation，用户重新确认。 | [用户] |
| D16 | 澄清页主 UI 是 AI 对话，辅 UI 是需求列表/编辑器；用户点“新增对话”开始；AI 自动读取版本上下文/附件/代码/知识，头脑风暴，创建 draft 需求；用户单条/批量确认。 | [用户] |
| D17 | 取消“澄清问题/决策问题”独立面板；开放问题内联对话卡片，决策落入需求版本/对话记录。 | [用户] |
| D18 | AI 不能替用户确认需求，不能删除需求；只能创建/修改 draft、提议回退；回退需用户确认。 | [推导] |
| D19 | 新对话获得“版本上下文包 + 历史线程摘要 + 相关产物引用”，不回放全部聊天记录。 | [推导] |

## 5. 设计与用例

| # | 决策 | 来源 |
|---|---|---|
| D20 | 用例模型：**需求 → 场景 → 用例** 三级；用例 = 逻辑对象 + 不可变版本；场景/用例携带 SUT 目标；用例步骤可覆盖跨 SUT。 | [用户] |
| D21 | 确认粒度 = 单用例 / 单场景下全部用例 / 单需求下全部用例；确认即冻结该用例版本；执行团队只领取最新已确认版本。 | [用户] |
| D22 | 已确认用例被 AI/用户修改 → 生成新 draft、退出可执行集；用户重新确认后恢复执行。 | [推导] |
| D23 | 用例设计页 = 脑图 + AI 对话；**没有“AI 生成”按钮**；用户点“新建对话”开启设计轮次，设计团队自己扫描所有待设计已澄清需求并实时渲染/更新脑图。 | [用户] |
| D24 | 设计团队在首轮设计后继续负责版本覆盖：执行发现缺口/stale → 自动产 draft 用例 → 用户确认，不需要新设计对话。 | [用户] |
| D25 | **A+**：默认新增需求需用户到设计页新建对话激活设计；已激活范围内的需求版本变化/用例 stale/执行缺口自动补 draft；当前设计对话活跃时新需求自动并入本轮；版本级开关 `auto_design_new_requirements`（默认关）可开启“新需求自动开设计轮次并自动建设计对话”。 | [用户] |
| D26 | 设计团队内部角色：Design Host、Design Planner、Case Author、Design Critic、Data Planner；取消“设计评审”人工页签与整版基线冻结。 | [推导] |
| D27 | 脑图导出保留 0.1 的 Markdown/Mermaid/OPML 能力；是否增加 CSV/Excel 待定。 | [假设] |

## 6. 执行与交付

| # | 决策 | 来源 |
|---|---|---|
| D28 | 执行团队**自主领取**最新已确认用例，无“开始执行”按钮；确认即入队，自动组织波次。 | [用户] |
| D29 | 同版本同时只有一个活跃波次；波次内按并发上限执行；运行中新确认用例进下一波；波次结束自动失败分析/问题/报告/覆盖缺口。 | [用户] |
| D30 | 执行上下文包含：用例版本 + 需求版本 + SUT/环境绑定 + 账号 + 目标库 + 代码基线；按步骤路由到 SUT。 | [推导] |
| D31 | 暂停/恢复是执行控制能力，不作为版本状态；支持波次级/用例句级暂停。 | [推导] |
| D32 | 问题状态 `open/confirmed/dismissed/merged`；支持重开回 open（原因/次数/历史）、手工合并、跨波次稳定 dedupe key；旧报告 as-of 不可变。 | [用户] |
| D33 | 报告以 HTML 为权威产物，PDF 由独立 headless 渲染 worker 生成；内置模板 + 章节开关；报告 revision 冻结。 | [用户] |
| D34 | 跨版本知识为**系统级**，不是版本级；版本只作为来源/证据；全局知识页 + 显式晋升 + 审核 + 澄清/设计注入。 | [用户] |

## 11. 明确不做 / 后置

- 多用户协作/读写锁/站内通知（0.1 P9 候选，不在 0.2 清单）。
- 非 PostgreSQL 目标库断言。
- 外部工单/CI/IM/Webhook 集成。
- 多租户/复杂 RBAC。
- 生产级安全加固/密钥托管/多区域 HA。
- 自动扩缩容、Redis/NATS/对象存储（除非 D67 后续调整）。

## 11a. 评审修订（2026-10-31）

- 交付基线按 **选项 C（P0–P8 全功能对齐 + P9）** 修正，capability-matrix 已改判。
- 统一 CaseVersion：需求变化→stale；新版本确认后旧 confirmed→superseded；执行只认 current+confirmed。
- 新增 `execution_intent`（case_version/环境/代码基线/purpose/attempt/status），驱动自动执行、重跑与收尾。
- 执行层统一 `version_sut_id`；补 `default_version_sut_id`、账号角色、多 SUT 上下文。
- 补 `requirement_confirmation`、`case_confirmation`、`requirement_closure`、`requirement.goal_met`。
- 报告改 `report` + append-only `report_revision` + `report.render_pdf`；新增 `export` 实体。
- 新增执行器注册/心跳/容量/排空与 `dispatch_epoch` fencing。
- 统一版本状态迁移表与收尾谓词；补 `human_request` API/UI/流程。
- **D25 已拍板 A+**：默认新需求需新设计对话；变化/缺口自动补；当前轮次自动并入；版本级自动开关（默认关）。其余开放问题见 §12。
