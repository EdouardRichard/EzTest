## Measurement method

- **8-concurrency batch execution**: the script creates one executing version with 8 fixture cases and 8 imported fixture sessions, starts one real batch through the running API/executor, polls the batch and case-run endpoints during the run and requires a `done` batch, 0 non-passed case run(s) and an observed maximum of at least 8 concurrently running case runs. The API must be started with the executor configured and `EZTEST_EXEC_MAX_CONCURRENT_CASES=8`; a lower cap produces an observed-concurrency FAIL.
- **Analysis non-model overhead**: one real P4 analysis is triggered (`force=true`) on the seeded fixture repository. The wall time from the trigger to the terminal state is measured; the model-call time is summed from the JSONL log of the loopback timing proxy placed in front of the deterministic fake LLM (`-LlmCallLogPath`) that the API was started against, and the difference is the non-model overhead. The local acceptance budget is 5000 ms for this one-file fixture; the configured analysis timeout (240 s) bounds the run. When the proxy log is not supplied or records no model call, the wall time itself is reported as an upper bound. Unrelated model calls sharing the same proxy during the window would be subtracted too, so the method can only under-report (never inflate) non-model overhead; measure a quiet local API for the exact figure.
- The P4 analysis gateway snapshots its LLM configuration at API startup, so the fake LLM/proxy must be wired at startup; this script does not patch the configuration. Only a local acceptance measurement is claimed - never a production SLA.
- The 8-concurrency row creates a `P8 SLO concurrency <stamp>` fixture version, system/environment/account/access, eight sessions and one batch in the local database. They are left in place after the run (the autonomous follow-up chain may reference the batch); the e2e/acceptance database reset owns cleanup.
