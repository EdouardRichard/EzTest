# EzTest 实施 Phase 规划 v1.0（从基础层开始）

> **性质**：实施节奏规划，不含接口/DDL/任务拆解（规格在各 Phase 启动时产出）。
> **依据**：`system-blueprint.md` v2.2（设计冻结候选）。
> **原则**：基础层先行 → Agent 运行时先行 → 领域/业务垂直切片 → 全自主闭环 → 体验与硬化。每个 Phase 都产出可演示、可验收的切片（含前端），不做"只后端"的阶段。
> **编号约定**：`P0–P8` 仅指本文的实施阶段；其他详细设计的局部里程碑使用独立前缀（`CI-Mx`/`AS-Mx`），不得复用。前端交付归属见 §2.9。

---

## 0. 规划原则

1. **Foundation first**：先解决"工程/数据/事件/认证/模型/Agent 运行时"这些一旦定错、后面全返工的地基；业务功能在 Phase 2 之后才开始。
2. **Agent runtime is the core**：Agent 运行时（会话/工具/活动流/上下文/预算）必须早于任何业务 Agent；它是所有后续阶段的公共底座。
3. **Vertical slice**：每个 Phase 都包含后端 + 前端 + 可演示流程 + 验收；不攒到最后一次性做 UI。
4. **Contract freeze gates**：事件模型（activity/SSE）、Agent 工具契约、核心领域实体在 Phase 0/1 冻结 V1；后续兼容扩展，避免边写边改。
5. **Risk-first spikes**：在基础阶段用最小 spike 验证高风险假设（SSE 断线回放、Playwright 执行、Session 注入、AI 代码理解证据校验），失败早暴露。
6. **两条并行轨道**：后端/Agent 轨与前端轨并行；代码理解与澄清/设计可并行；但依赖关系不跨越（见 §2）。
7. **可降级**：AI 代码理解不可用 → 文件级；Session 自动登录未就绪 → 人工导入；LLM 故障 → 重试/提示。每个 Phase 都要定义降级路径。

## 2. 各 Phase 详情

### P0 工程与运行基础（2–3 周）

**目标**：任何业务功能之前，先有"能跑、能观测、能鉴权、能实时、能调模型"的地基。

**范围**
- 工程脚手架：后端（Go）+ 前端（Next.js）+ PostgreSQL + Docker Compose + 本地开发脚本；lint/test/build 基线。
- 配置/环境变量/日志/统一错误模型/请求 ID/审计骨架。
- 数据库迁移框架（幂等、可重入、启动即迁移）。
- 对象/证据存储抽象（本地文件 + sha256；为后续证据/截图/代码事实证据服务）。
- 认证与用户：单管理员 + 普通用户；登录/登出/token；权限基础（管理员/普通用户）。
- API 骨架：JSON 错误约定、分页、幂等 request_id、健康检查、OpenAPI 文档骨架（可选）。
- **SSE 通道骨架**：事件发布/订阅、事件持久化、单调 seq、快照游标、Last-Event-ID 回放、心跳、重连语义；提供无版本实体时的平台测试流。
- 极简 LLM 网关：模型/地址/Key/自定义请求头/重试次数/重试间隔/多模态图片输入/流式与非流式。
- 前端壳：登录/登出、用户菜单、侧边栏、路由、状态徽章/主题/空页面、SSE 客户端 hook、请求封装；最小设置页（用户列表/创建、LLM 配置与连通性/多模态测试）。
- 风险 spike（最小）：SSE 断线回放、LLM 多模态一次请求、浏览器执行环境可用性（只验证不集成）。

**明确不做**：任何领域实体（版本/需求/用例/执行）、Agent 业务、目标环境接入；设置页仅限平台运维（用户/LLM），不含 Agent/业务配置。

**退出标准（Definition of Done）**
- 管理员可登录、通过设置页创建普通用户；权限差异生效。
- 健康检查/日志/审计可用；迁移重复执行无副作用。
- 前端能收到测试 SSE 事件，断线重连不丢事件（按 seq/游标验证）。
- 管理员可在设置页配置 LLM，并完成一次多模态调用（含图片）；重试策略生效。
- 目录/构建/运行文档齐备。

**风险**：事件模型/SSE 契约一旦被业务使用就难改 → 本 Phase 必须先冻结 V1 契约；LLM 网关避免过度设计。

### P1 Agent 运行时地基（3–4 周）

**目标**：让"一个 Agent 能对话、能调工具、能实时展示、能中止/回放"跑通，作为所有业务 Agent 的公共底座。

**范围**
- Agent 会话与上下文：system/user 组装、历史/transcript、上下文窗口/压缩钩子（先做简单截断，压缩后置）。
- 工具注册与权限：工具描述/schema、调用执行、错误模型、超时/取消、审计；最小工具集（文件只读、HTTP 只读、测试工具）。
- **活动事件**：thinking/text/tool_use/tool_result/decision/usage；写入 DB + SSE 实时推送（复用 P0 通道）。
- 预算与中止：步数/时长上限、手动中止、收尾钩子（先做"中止即停 + 事件标记"）。
- Agent 配置雏形：角色/提示词/模型（管理员可配，P1 先内置一个诊断 Agent（运行时验证夹具（非业务角色，见 D27）））。
- 前端：Agent 会话视图（工具调用折叠/展开、思考折叠、实时状态、中止按钮）、活动回放。
- 风险 spike：Playwright 最小执行（打开页面/截图）与 Session 注入的最小验证（不接入业务）。

**明确不做**：13 个业务 Agent、双图/黑板、多 Agent 协作、业务工具（浏览器正式执行/DB 断言等）。

**退出标准**
- 诊断 Agent 可完成"多轮对话 + 工具调用 + 结果"，全过程在 UI 实时可见、可回放。
- 可中止一次运行，事件与状态正确；工具错误/超时不会拖垮服务。
- Agent 配置（提示词/模型）改动可生效（重启或热加载均可）。
- 事件/工具契约冻结 V1（后续兼容扩展）。

**风险**：这是核心底座，接口设计要稳；不要把业务逻辑塞进运行时。

### P2 公共资源与身份（3–4 周）

**目标**：把"被测系统/环境/账号/会话/本地代码仓"配好、管好，为设计/执行提供前置。

**范围**
- 系统 / 环境 / 应用模型（页面/路由/接口/组件的登记与展示；应用模型可先支持人工/导入，自动探索在 P5）。
- 账号 + AccountSystemAccess（登录方式/凭据**明文存储**，D28，无加密/脱敏）+ Session（生命周期/状态机/租约/人工导入 storageState/校验/失效/人工接管占位）。
- 权限快照（首版可选：登录校验 + 基础能力探测；完整 ProbeRecipe 可后移）。
- 本地 Git 代码仓配置：本地路径、固定分支、include/exclude、只读挂载校验、索引状态占位（实际索引在 P4）。
- 管理 UI：资源列表/编辑、Session 面板（状态/有效期/接管）、代码仓配置页；普通用户只读。
- Session 自动登录**不在本 Phase 强求**：P0 先支持"人工导入 storageState"，自动登录在 P6 前补齐。
- Session 事件流与审计日志**不做**（D28）；凭据/Session 明文存储，不写 `audit_logs`。

**明确不做**：自动登录全流程、权限探测完整配方、代码索引（P4）。

**退出标准**
- 管理员可配置系统/环境/账号；人工导入 Session 后状态 valid，可被后续用例引用。
- Session 失效/撤销/人工接管路径可用（至少手工）。
- 普通用户只能查看/使用，不能改配置。
- 本地代码仓配置保存成功，能看到路径/分支/commit（索引占位）。

**风险**：凭据/Session 明文（D28）；人工接管流程尽早打通。

### P3 版本 / 多需求 / 澄清（3–4 周）

**目标**：跑通"版本级多需求 + AI 引导澄清 + 人确认"的垂直切片。

**范围**
- 领域：`version` 上下文 7 表——Version、Requirement（多需求）、RequirementRelation（依赖/冲突/重叠/共享范围）、RequirementAttachment、ClarificationSession、ClarificationQuestion、Decision；主键雪花 ID（D29），附件文件系统存储（D30）。
- 状态语义（D31）：Version 为**粗粒度容器**，需求流水线独立；P3 只实现 `draft→clarifying→designing` 与 `Requirement draft→clarified`；新增/确认/重开需求永不改变或回退 Version.status；`designing` 下仍可独立澄清/确认；新增需求不中断执行（P7）。
- 进入设计软门禁：允许带未澄清需求进入 `designing`，但需 `acknowledgeUnclarified=true`；未确认时 409 `unclarified_requirements`（details 含未澄清需求 id 与 open 问题数），确认后返回 `warnings` 并进入 `designing`。
- 资源绑定：创建版本时可选绑定 P2 系统/环境/代码仓（branch→commit 快照）；`draft|clarifying` 允许整体替换，`designing` 只读。
- Agent：澄清对话 Agent + 需求分析 Agent + 上下文侦察 Agent 最小版（读文档/截图/本地代码只读）；3 个 profile seed；11 个澄清/需求工具；附件截图以 `image_ref` 注入（data URL 仅 LLM 调用瞬态生成，不落库）。
- 前端：版本列表/创建版本（含可选资源绑定）；版本详情容器（VersionHeader + 状态徽章 + 9 Tab）与总览 Tab 骨架；版本工作台（需求列表 + 需求编辑器/附件 + 关系图 + 澄清对话 + 问题清单 + 决策 + 确认/重开 + 新增需求）；其余 8 个 Tab 以骨架/占位入口存在并标注归属阶段；脑图/资源为独立入口（P5/P2）。
- 实时：澄清过程经 `version:{id}` 通道 SSE 可见（快照游标 + Last-Event-ID + 20s 心跳；复用 P0/P1）。
- 暂停/继续：本阶段只需"用户可随时离开/返回，状态不丢"（运行暂停在 P6）。

**明确不做**：脑图、执行、代码影响分析（P4/P5）；PDF/DOCX 附件、图片编辑/压缩、视觉断言。

**退出标准**
- 一个版本可录 3+ 需求，AI 多轮追问，人能回答/编辑，需求/关系/附件/问题/决策落库。
- 需求确认后 `draft → clarified`；Version 状态按 D31 只由创建/开始澄清/进入设计改变（`draft → clarifying → designing`），任何需求操作不改变或回退 Version.status。
- 刷新/重连不丢对话与草案；关系图正确渲染；附件上传/下载/删除走 D30 文件系统。
- AI 不可用时，人工仍能录入/确认需求（降级可用）。

**风险**：多需求关系（冲突/重叠）容易做成"看起来有"；本 Phase 只需基础关系 + 人工可编辑，复杂推理后移。

### P4 代码理解与影响分析 v1（3–4 周，可与 P3 并行）

**目标**：建立"本地 Git 真源 → AI 代码理解 → 变更影响"能力，为设计/增量执行提供依据。

**范围**
- T0 通用层：只读 git、文件树、commit、文件级 `git diff`、文件级锚点。
- T1 AI 代码理解：读变更/相关文件 → 页面/路由/接口/组件/依赖/变更语义；**证据存在性校验**（path/line/摘录哈希）、置信度分级、按 commit/文件哈希/模型/提示词版本缓存与版本化。
- 跨栈 API 契约：前端调用点 ↔ 后端接口端点（AI 识别，不假设语言）。
- 影响分析 v1：代码 diff + 需求关系 + 锚点 + AI 推理 → 受影响用例候选；`unmapped_changes` 显式提示；人工可调整。
- 前端：代码仓管理页（P2 已有配置）补索引状态；版本详情"代码与变更"Tab 基础（diff/影响/未映射/commit）。
- 降级：AI 不可用 → T0 文件级影响 + 人工确认。

**明确不做**：parser/静态解析、符号级调用链、字段级分析（不做 parser 是设计决策）。

**退出标准**
- 任意语言仓库可做文件级 diff；AI 能识别变更涉及的接口/路由/页面/关键逻辑并给出证据。
- 同 commit 重跑影响分析结果复用缓存且一致；AI 重分析产生新版本不覆盖。
- 影响结果带原因/置信度/证据，可人工勾选；未映射变更可见。
- AI 失败时主流程降级不阻塞。

**风险**：AI 事实质量 → 证据校验 + 置信度 + 人工修正闭环先在 P4 打通；否则 P7 的增量批次会不可信。

---

### P5 用例脑图与评审（4–5 周）

**目标**：把"需求 + 代码现状 + 应用模型"变成可评审的用例脑图。

**范围**
- 应用探索 Agent（基础）：基于环境/人工 Session 探索页面/接口，补全应用模型（只读）。
- 测试设计 Agent：需求图 + 关系 + 应用模型 + 代码事实 → 用例脑图（场景/步骤/断言/数据/前置/优先级）。
- 设计评审 Agent：覆盖/断言/可执行性/重复/代码有但脑图没覆盖（AI 辅助）。
- 数据/前置规划 Agent（最小）：所需账号/Session/数据/cleanup（与 P2 资源对接）。
- 脑图领域/API/UI：树/图视图、编辑步骤与断言、评审通过/驳回、冻结基线、导出 Markdown/Mermaid。
- 锚点：需求↔用例↔代码/页面接口。

**明确不做**：执行、AI 补全、问题/报告（P6/P7）。

**退出标准**
- 从确认需求生成脑图；人可编辑/评审；批准后成为基线并导出。
- 脑图节点带来源（人工/AI）与代码锚点；关系正确。
- AI 不可用时，人可手工建/改脑图，流程不阻断。
- 脑图评审 SSE 实时可见。

**风险**：脑图生成质量依赖 P3/P4 输入质量；本 Phase 先保证"可评审、可编辑、可导出"，质量在 P8 评测迭代。

---

### P6 执行引擎与证据（5–6 周，最大风险阶段）

**目标**：AI 真实执行基线用例：浏览器/API、取证、暂停/恢复、失败分类、实时可见。

**范围**
- 领域：RunBatch、CaseRun、StepRun、StepResult、Evidence、RunEvent。
- 执行引擎：批次计划、用例调度/并发、依赖与资源冲突、步骤检查点。
- 暂停/恢复：`paused` 独立标记、优雅/立即、恢复从检查点；interrupted 用例 cleanup/seed。
- 工具：Playwright（导航/DOM/A11y/点击输入/截图/storageState）、HTTP/API、DB 断言（可选只读）、日志/控制台、文件/下载。
- Session：自动登录（补齐 P2）+ 注入 + 失效重取；人工接管 checkpoint。
- 证据：截图/报文/日志，文件系统存储（D30）+ sha256 完整性 + 不可变；四态结果（passed/failed/blocked/inconclusive）；失败分类 v1（应用/环境/会话/模型/用例/flaky）。
- 前端：版本详情内执行类 Tab（执行会话/探索链路/实时播报/结果与证据）、执行实时视图（多 Agent 会话/工具/证据）、暂停/恢复按钮、人工接管卡。
- 报告 Batch 1 简版（完整报告在 P7）。

**明确不做**：AI 自主补用例、失败分析 Agent、问题/报告完整、完成后增量（P7）、视觉断言（P8）。

**退出标准**
- 基线用例在真实测试环境执行；AI 能取证；失败分类正确区分"应用失败/环境/会话/模型"。
- 暂停（优雅/立即）与恢复可用；重启后未完成用例状态正确（interrupted/blocked）。
- 实时视图能看到执行过程与证据；报告 Batch 1 可导出。
- 环境/账号受限时能 blocked 并说明原因。

**风险**：执行不稳定、环境/Session 问题、浏览器工具差异 → 先用 1–2 个稳定测试环境跑通，再扩；失败分类宁严勿松。

---

### P7 全自主闭环与交付（4–6 周）

**目标**：从"会执行"到"自主补全 + 失败分析 + 问题/报告 + 完成后增量"。

**范围**
- 探索/补全 Agent：执行中分析覆盖缺口/遗漏 → 新增用例（`ai_supplement`）→ 回填脑图 → 继续执行（受需求/环境约束，不改基线）。
- 失败分析 Agent：根因分类、去重、置信度、重跑建议、问题候选。
- 问题整理 + 报告：问题（含证据/代码位置）、版本报告（批次/差异/stale）、脑图导出、报告导出。
- **继续中（continuing 硬状态）**：完成后新增需求 → 增量澄清 → 增量设计/影响分析（P4）→ 增量批次 → 报告批次差异；暂停/恢复支持 continuing。
- AI 补充用例自动并入并标记；报告区分基线/补充。
- 前端：继续中状态徽章/横幅与新增需求入口、变更与批次、问题页、报告页（批次切换/差异）。

**明确不做**：知识沉淀/评测（P8）、多用户协作、外部工单。

**退出标准**
- 执行中 AI 能发现覆盖缺口并补用例，回填脑图且不阻断执行。
- 完成后新增需求触发 continuing → 增量批次 → 新报告版本；支持暂停/恢复。
- 问题带步骤/证据/代码位置；报告分批次、evidence stale 标记。
- AI 补全/失败分析不可用时，降级为纯基线执行 + 人工查看（不崩）。

**风险**：自主循环容易"自嗨扩用例" → 补全边界（需求/环境）与预算/终止条件必须在 P7 定义并验收。

---

### P8 体验完善与硬化（4–6 周）

**目标**：从"能跑"到"可长期使用/可扩展/可运维"。

**范围**
- 前端完整：版本切换器、全局搜索、待办中心、需求/澄清与脑图回版本详情 Tab、代码与变更完整版、探索链路交互完善、Agent 中心（配置/运行观察）、设置完善（用户/LLM）、报告优化、空/错/重连/移动端最小适配、可访问性。
- 质量：Agent 评测集（设计覆盖/影响命中/失败分类准确/问题误报/补充命中）、AI 代码事实质量指标、影响分析漏报/误报度量、回归基线。
- 视觉断言（D7）：截图基线、像素/区域比对、阈值与失败分类；纳入 P8 评测集。
- 知识沉淀（D4）：版本内复用 + 人工审核入库（P7 已声明归入 P8）。
- 非功能：性能/并发/限流、长跑资源清理、备份恢复演练、安全审计（秘密/代码/权限）、审计日志、部署与运维文档。
- P2 可选：多用户协作（读写锁/评审）、外部工单预留、环境编排（若需要）。

**退出标准**
- SLO 达标（首屏、执行并发、代码分析时延）；压测/故障恢复演练通过。
- 评测集可跑出指标并作为回归门禁。
- 文档齐备（部署/运维/用户/开发），可交接。

**风险**：范围膨胀 → 严格按 P0–P7 已交付功能做体验与硬化，不新增业务能力；P2 项默认不做。

## 4. 里程碑与门禁

| 里程碑 | 对应 | 含义 |
|---|---|---|
| M0 地基可用 | P0 | 登录/迁移/SSE/LLM/前端壳+设置页跑通 |
