## 2. 核心决策速查（D1–D24）

| 主题 | 结论 |
|---|---|
| 定位 | AI 全自主端到端功能测试（Web + API）；版本级多需求；人最小参与 |
| Agent | 13 个逻辑角色（职责不合并、部署可合并）；Agent 能力是系统核心，不简化 |
| 人工点 | 澄清回答、脑图评审、登录接管、报告阅读；升级仅四类 |
| 生命周期 | 暂停（优雅/立即）；完成后新增需求 → **continuing 硬状态** → 增量批次；报告按批次 |
| 脑图 | 基线人工评审一次；AI 补充用例自动并入；增量默认不评审 |
| 代码 | **本地 Git 为唯一真源**、只读挂载、固定分支、monorepo 支持；**语言无关**：不限定被测项目语言/技术栈，AI 代码理解为主，**不设计 parser**；代码级影响分析（diff + 需求关系 + 锚点 + 跨栈 API 契约） |
| 代码事实 | T0 通用层（文件树/diff/锚点）+ T1 AI 理解（事实带证据+置信度、缓存/版本化）；按需 `code_read` 下钻；低置信只作线索；未映射变更显式暴露 |
| 前端 | 不简化（ARTEX 级）；P0 Tab：总览/执行会话/探索链路/实时播报/结果与证据/问题/报告/代码与变更 |
| 平台 | 单管理员+普通用户、公共资源、极简 LLM（重试/头/多模态）、无多租户/CI/工单/环境编排 |

完整决策记录见主蓝图 §3.2。

## 3. 实施 Phase 规划（摘要）

> 权威计划：[implementation-phases.md](implementation-phases.md)。**从基础层开始**，每个 Phase 都有可演示闭环、退出标准与门禁。

| Phase | 主题 | 关键验收 |
|---|---|---|
| P0 | 工程与运行基础（脚手架/迁移/存储/认证/API/SSE/LLM/前端壳） | 登录、迁移、SSE 回放、LLM 多模态、前端壳跑通 |
| P1 | Agent 运行时地基（会话/工具/活动流/上下文/预算） | 一个 Agent 实时可观察、可中止、可回放 |
| P2 | 公共资源与身份（系统/环境/应用模型/账号/Session/本地代码仓） | 配置资源；Session 人工导入/失效/接管；代码仓只读配置 |
| P3 | 版本 / 多需求 / 澄清 | 3+ 需求多轮澄清 + 关系 + 确认闭环 |
| P4 | 代码理解与影响分析 v1 | 任意语言文件级 diff；AI 事实+证据；影响候选 + 未映射 |
| P5 | 用例脑图与评审 | 生成脑图、评审通过、导出、代码锚点 |
| P6 | 执行引擎与证据 | 真实执行、暂停（优雅/立即）/恢复、取证、失败分类、实时视图 |
| P7 | 全自主闭环与交付 | AI 补全、失败分析、问题/报告、继续中增量批次 |
| P8 | 体验完善与硬化 | 前端完整、Agent 中心、评测、性能/备份/审计 |

- **关键路径**：P0 → P1 → P3 → P5 → P6 → P7；P2、P4 可部分并行；前端贯穿每个 Phase。
- **门禁**：每个 Phase 结束需通过退出标准 + 文档同步 + 关键路径自动化测试 + 演示；未达标不进入下一 Phase（可裁剪范围，不跳过地基）。

## 4. 如何使用这套设计推进多阶段开发

1. **每个 Phase 启动时**：读主蓝图对应章节 + `implementation-phases.md` + 相关详细设计 → 产出 `phase-N-spec.md`（接口契约、DDL、任务拆解、风险、验收用例）。
2. **开发中**：设计变更必须回写文档（决策记录 + 章节更新），避免"代码与设计漂移"。
3. **阶段验收**：按 `implementation-phases.md` 的退出标准逐条演示；通过后进入下一阶段。
4. **跨阶段约束**：领域模型（版本/需求/脑图/批次/证据/问题/代码锚点）与事件/API 契约尽量早冻结；新增字段/事件按兼容方式扩展。
