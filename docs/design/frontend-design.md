## 1. 设计原则

1. **AI-native**：页面主体是"AI 在做什么 + 做到哪 + 凭什么结论"，不是传统测试用例表格。
2. **可观察**：每个 Agent 的思考/工具调用/结果/证据都可回放；实时流 + 历史回放。
3. **可干预**：暂停（优雅/立即）/恢复、新增需求、人工接管、升级处理都在显眼位置。
4. **可追溯**：问题/结论 → 用例 → 步骤 → 证据 → 需求/**代码位置**，处处可深链。
5. **状态永远可见**：版本/批次/用例/Agent/流状态、实时/重连中、暂停原因；"继续中"硬状态不可含糊。
6. **渐进披露**：概览给结论与异常，细节按需展开（工具调用折叠、证据抽屉、diff 抽屉）。
7. **桌面优先**：1280 起，支持 1024+。

视觉与组件（对齐 ARTEX 风格）：
- 深/浅色主题；侧边栏 + 内容卡片；圆角卡片 + 细分隔线；状态徽章全站统一（一处色板/文案定义）。
- 图标 lucide；空状态/骨架屏/错误重试统一。
- **ActivityFeed / Transcript**：思考、工具调用、结果、证据、决策、门禁、状态变更分行渲染；折叠 + 懒加载。
- **EvidenceViewer**：截图 lightbox、HTTP 请求/响应双栏、日志、**代码 diff 抽屉**。

- **HumanGateCard**：评审/接管/升级内联卡 + 待办中心。
- **CodeLink**：`file:line` / 路由 / 接口 → 代码查看器；用例/问题/证据均可挂。

### 4.3 各 Tab 细节（首版目标；按实施阶段交付）

#### 4.3.1 总览
- 4 张卡：需求覆盖（分母/已确认/已验证）、用例结果（通过/失败/阻塞/未执行）、问题（按严重级）、当前批次（Batch N / commit）。
- 需求×用例覆盖矩阵（小图，可展开）。
- Agent 状态卡：仅显示活跃/等待角色，点击跳会话。
- **代码变更摘要**：changed files + 影响用例数 + 受影响页面/接口。
- 批次时间线：Batch 1（commit）→ Batch 2（commit + 新增需求）…。
- 待办入口：待评审脑图、待接管、待升级决策。

#### 4.3.2 执行会话（AI 执行过程）
- 左栏会话列表：按团队/Agent 分组（编排/澄清/设计/执行#1..N/补全/失败分析/报告），行内显示状态、当前用例、未读、脉冲。
- 右栏 transcript：Agent 思考（折叠标"含推理"）、工具调用一行折叠（展开参数/结果/耗时/证据）、断言期望 vs 实际、证据内嵌、人工关卡卡。
- 顶部过滤：Agent / 用例 / 类型 / 仅异常；搜索。
- 操作：暂停/恢复（优雅/立即，版本级）、向执行 Agent 发纠偏消息（steer）、跳转证据/用例/代码。
- 状态位："实时"/"重连中"，禁止把断线渲染成"没消息"。

> **P6 实施注记**：`SessionsTab` 已落地：左栏按 Agent/用例分组（状态、当前用例、未读脉冲），右栏复用 agent-console 的 `Transcript`（`session-adapter.ts` 把 P1 `agent.activity` 映射为 `AgentEvent`，不改 agent-console）；工具调用一行折叠、断言期望 vs 实际、证据按钮打开 `EvidenceViewer`；顶部过滤/搜索与 `stream-status`；`HumanGateCard` 在 transcript 内呈现待接管。数据来自 `useExecution` 的会话列表 + `version:{id}` 事件流。

#### 4.3.3 探索链路（Execution Chain Graph）
- 节点：需求（粗描边方块）、用例（状态色圆角卡）、执行结果（小圆点：通过绿/失败红/阻塞灰/未执行白）、问题（红色菱形）、AI 补充用例（虚线 + "AI" 角标）、受影响用例（黄色描边 + `needs_revalidation`）。
- 边：`需求→用例`（派生）、`用例→结果`（产出）、`结果→问题`（引发）、`缺口→补充用例`（补全）、`新需求/代码变更→受影响用例`（影响）。
- 实时：执行节点脉冲/边动画；新结果、新问题、AI 补充即时出现。
- 交互：缩放/平移/MiniMap；节点抽屉（摘要 + 证据 + 代码 + 深链）；筛选（需求/状态/仅异常/AI 补充）；"跟随当前执行"自动聚焦。
- 大图：按需求折叠、按需展开；后端增量推送。

> **P6 实施注记**：`ExplorationTab` + `ChainGraph`（手写 SVG，`chain-layout.ts` 确定性布局）渲染「需求→用例→结果」三层；状态色 + 图标/文本双编码；需求/状态/仅异常筛选、节点抽屉（摘要/证据/深链）、节点过多时按需求折叠。P6 不抓取问题数据，问题节点显示 P7 空态（`chain-issue-placeholder`），不引入图库。

#### 4.3.4 实时播报（Broadcast）
- 全量事件倒序：时间、Agent、动作、摘要、链接；异常置顶。
- 过滤：事件类型、Agent、严重级。
- 与链路/会话互补：链路看结构，播报看流水。

> **P6 实施注记**：`BroadcastTab` 消费 `version:{id}` 事件流（含 `agent.activity`），倒序、异常置顶、按事件类型/Agent 过滤、快照游标分页，点击深链到用例/证据；P6 不含问题事件（P7）。

#### 4.3.5 结果与证据
- 用例结果表：用例、状态、耗时、步骤、问题、证据数、批次、代码锚点；失败/阻塞置顶。
- 步骤详情：步骤、动作、期望、实际、结论、证据、**代码位置（file:line / route / API）**。
- 证据查看器：截图 lightbox（支持前后对比）、HTTP 请求/响应双栏（复制 curl、diff）、日志/控制台搜索。
- 失败分类标签（应用缺陷/环境/会话/模型/用例问题）来自失败分析 Agent。
- 操作：重跑用例、批量重跑受影响用例、跳转问题。

> **P6 实施注记**：`ResultsTab` + `EvidenceViewer` + `StepDetail`/`AssertionRows`/`FailureClassBadge` 已落地。结果表支持失败/阻塞置顶、步骤/断言展开、终态重跑；证据查看器经 `/api/versions/{id}/evidence/{id}` 带 Bearer 读取（`apiStreamFetch` + object URL），按 `kind` 渲染：截图 lightbox、HTTP 请求/响应双栏 + 复制 curl、console 搜索、download 链接；展示 sha256/大小/MIME，不显示文件系统路径；Esc/遮罩关闭、焦点还原、Tab 焦点环。失败分类标签来自 `failure_class`（application/environment/session/model/case），flaky 为派生展示。

#### 4.3.6 问题
- 列表：严重级、标题、状态（open/confirmed/dismissed）、关联需求/用例、证据数、批次、代码位置。
- 详情：复现步骤、期望/实际、证据、环境/Session 指纹、相关需求、**代码锚点**、建议。
- 操作：确认/驳回（原因）、复制 Markdown/工单格式、跳转证据/用例/代码。

#### 4.3.7 报告
- 批次报告：范围、执行摘要、需求覆盖矩阵、用例结果、问题列表、风险与结论、附录（环境/账号/Session/commit/时间）。
- 批次切换 + 差异对比（新增问题/已修复/回归通过）。
- 导出：Markdown、脑图（Mermaid/PNG）；PDF 后续。
- 条目深链到证据/用例。

> **P6 实施注记**：`ReportTab` + `ReportSummary` 落地 Batch 1 派生报告：批次切换、摘要卡（用例数/四态分布/分类/证据数/耗时）、用例明细、Markdown 导出（服务端流式 + `X-Content-SHA256`）；不含问题列表/批次差异/Report Revision（P7），导出中/失败有明确状态。

#### 4.3.8 代码与变更（关键资产）
```text
[批次 Batch 2] 代码基线: repo@abc1234 → def5678    [刷新索引]
变更文件: 34 个 | 变更实体: 路由 5 / 组件 8 / 接口 12 | 影响用例: 17 | 受影响页面/接口: 9

┌ 变更文件/实体 ──────────────────────┬ 映射与被影响 ─────────────────────────┐
│ src/pages/order/list.tsx    +120/−30 │ 页面 /orders → 用例 C41,C44,C45        │
│ src/api/refund.ts           +45/−10  │ 接口 POST /api/refund → C52,C53        │
│ ...                                  │ 受影响用例 (needs_revalidation)         │
└──────────────────────────────────────┴────────────────────────────────────────┘

批次时间线: Batch 1 (commit aaa) → Batch 2 (commit def, 新增需求 R4/R5, 影响 17 用例)
操作: 查看 diff / 重跑受影响用例 / 复制影响面
```
- diff 查看器：文件列表 + 行级 diff + 变更实体提取（路由/组件/接口/符号）。
- 代码↔用例映射：点击任意实体看关联用例、需求、历史问题。
- 无代码变更时显示"本批无代码变更"。
- 影响分析结果可人工调整（勾选/取消用例）后再执行。

- **设置（PG10）**：用户、LLM（多模态/重试/头）、基础配置（实施 P0 起提供最小版）。

## 5. 关键交互流程

### 5.1 暂停 / 恢复（允许立即暂停）

```text
执行中/继续中 → 点[暂停] → 弹窗：
   ○ 优雅暂停（默认）：当前步骤完成后停止
   ○ 立即暂停：中断当前步骤/工具调用（二次确认：可能产生半完成状态，该用例将标记 interrupted）
→ paused=true（主状态不变）；顶部横幅：已暂停 · [恢复] · [新增需求] · 已完成步骤 N/M
→ 恢复：从最后完成步骤检查点续跑；interrupted 用例先 cleanup/seed 再重跑
```
- 暂停期间仍可查看实时视图、证据、代码变更；可新增需求（见 5.2）。
- "继续中 + 已暂停"同时显示：`继续中（第 2 批）· 已暂停`。

> **P6 实施注记**：`PauseDialog` 默认优雅；选「立即暂停」后原地展示中断警告（同一「确认立即暂停」按钮即二次确认），不另开弹窗；请求 in-flight/错误状态由 header 持有，提交后通过事件/轮询确认。`PausedBanner` 显示模式、已完成步骤数与恢复入口。优雅暂停把运行用例回 `pending`（不产生 `interrupted`），立即暂停置 `interrupted` 并记 `interrupted_step_seq`；暂停期间仍可浏览其余 Tab。

### 5.2 完成后新增需求 → 继续中（硬状态）

```text
completed 版本 → 点[新增需求] → 录入（文本/文档/截图，可多条）
→ status = continuing（硬状态）；continue_phase=clarifying；batch_no+1；记录 base/head commit
→ 自动进入"需求与澄清"：AI 增量澄清（新增需求 + 与既有需求关系）→ 人确认
→ continue_phase=designing：增量脑图 + 影响分析（代码 diff + 需求关系 + 锚点）
   → 默认自动进入执行（可选"执行前查看增量脑图"）
→ continue_phase=executing：只执行新增 + 受影响用例
→ status=completed：报告出现 Batch N + 差异
```
UI 要点：
- 已完成页常驻"新增需求"入口；状态徽章立即变为"继续中（第 N 批）"。
- "代码与变更"自动展示本批 commit diff 与影响用例；用户可调整受影响用例。
- 暂停期间新增需求：澄清完成后提示"将恢复执行增量批次"。

### 5.3 脑图评审

```text
reviewing → 横幅"待评审" → 全屏脑图 → 编辑/评论 → [通过并开始执行] / [驳回]
→ 通过：基线冻结，status=executing；执行中 AI 补充节点自动并入并标记
```

### 5.4 登录接管 / 升级

- 播报/会话中生成"待人工处理"卡，同时进入顶栏待办。
- 接管卡：原因（2FA/验证码/审批）、账号/系统、操作指引、完成按钮；完成后自动继续。
- 升级卡：上下文摘要（发生什么/已尝试/需要决策）+ 选项；人选择后继续。

> **P6 实施注记**：`HumanGateCard` 由 `caseRun.pending_takeover` 渲染原因（MFA/验证码/审批）、账号/系统、操作指引、到期时间；仅 admin 显示「完成接管」并打开既有 `TakeoverDialog`（复用 P2 `POST /api/resources/takeovers/{id}/complete`），普通用户只显示只读提示；完成后卡片消失、事件刷新并自动重排新 attempt。若根本没有 Session 行（manual/未配置配方），只提示 `blocked(session, no_session)`，不生成接管卡。

## 6. 实时协议（SSE）

- 端点：`GET /api/versions/{id}/stream?since={cursor}`；支持 `?agent=&case=` 过滤。
- **快照游标**：首屏 REST 取最新事件页（返回 `snapshot_cursor`），SSE 从游标开始；历史 ≤cursor、实时 >cursor，无洞。
- 事件字段：`seq`（全局单调）、`type`、`version_id`、`batch_id`、`case_id`、`step_id`、`agent_role`、`session_id`、`ts`、`summary`、`detail`、`refs`（evidence/case/requirement/**code**）。
- 新增事件：`code.indexed`、`code.changed`、`code.impact_computed`。
- 去重：前端按 `seq`；断线自动重连带 `Last-Event-ID`；UI 显示"重连中"。
- 心跳 20s；反代关闭缓冲。
- 图/代码变更：事件驱动增量更新；复杂图可 2–5s 轮询兜底；结构签名不变不重渲染。

## 7. 状态与异常

- 空状态：无版本/需求/脑图/问题/报告/代码变更分别有引导。
- 错误：保留上次数据 + 重试；SSE 断开显示"重连中"，不显示"无数据"。
- 状态一致性：执行中/已暂停/继续中/已完成/待评审/待接管 在顶栏、横幅、列表一致。
- 权限：普通用户只读公共资源与 Agent 配置；只读态明确标注。
- 可访问性：键盘可达、焦点管理、对比度、图表不只靠颜色（加图标/文本）。
