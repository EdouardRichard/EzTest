# EzTest 0.1-preview — release notes

**Release:** `v0.1.0-preview.1` · **Date:** 2026-10-30 · **License:** Apache-2.0

EzTest is an AI-driven end-to-end functional testing platform for Web and HTTP API systems. This is the
first public preview: the complete requirements → clarification → code-aware test design → human-reviewed
case mindmap → autonomous browser execution → evidence, issues and per-batch reports pipeline, plus
incremental re-testing for new requirements.

> **Preview quality.** EzTest is a single-team, self-hosted preview. It is not multi-tenant, not
> production-hardened, and the Docker/Compose stack has only been statically validated by the
> maintainers. See [Status & limitations](https://github.com/EdouardRichard/EzTest/blob/main/README.md#status--limitations)
> in the README before relying on it.

## Quick start

```powershell
# Windows
Expand-Archive .\eztest-0.1.0-preview.1-windows-x64.zip -DestinationPath .\eztest
cd .\eztest
.\init-config.ps1 -DatabaseUrl "postgres://eztest:<password>@localhost:5433/eztest?sslmode=disable"
.\start-eztest.ps1
```

```bash
# Linux
tar -xzf eztest-0.1.0-preview.1-linux-x64.tar.gz
cd eztest-0.1.0-preview.1-linux-x64
bash install-linux-deps.sh
bash init-config.sh --database-url "postgres://eztest:<password>@localhost:5433/eztest?sslmode=disable"
bash start-eztest.sh
```

Then open <http://localhost:6868> and sign in with the seeded administrator. The generated
`EZTEST_ADMIN_PASSWORD` is stored in the package `.env` and is never printed by the scripts. Use
`status-eztest.*` to check the stack, `stop-eztest.*` to stop it, and `smoke-test.*` to verify the
installation end to end.

Alternative deployments: Docker Compose (`deploy/docker-compose.yml`, statically validated only) and
running from source (Go 1.24.6 + Node 22 + pnpm 11 + PostgreSQL 17). See the README for details.

## What is in this preview

- **Version & requirements workspace:** multi-requirement versions, requirement relations, attachments,
  AI clarification chat with questions and decisions.
- **Code-aware design:** read-only local Git indexing, evidence-checked AI code facts, diff-based impact
  analysis, and a reviewable scenario / case / step / assertion mindmap with requirement sources and code
  anchors.
- **Autonomous execution:** a separate Playwright executor drives a real Chromium browser; UI, API, text,
  database (read-only PostgreSQL) and visual assertions; immutable evidence (screenshots, network,
  console); graceful and immediate pause with checkpoint resume; human takeover for 2FA/captcha.
- **Delivery:** failure classification and analysis, issues with evidence and `file:line` anchors,
  per-batch report revisions with diff and stale detection, Markdown and mindmap export.
- **Autonomous loop:** AI coverage-gap supplement and incremental `continuing` batches selected by code
  diff plus requirement relations and anchors.
- **Observability:** SSE event streams with replay, execution sessions, real-time broadcast, exploration
  chain graph, audit log, global search and todo center.
- **Platform:** single admin + users, encrypted LLM credentials, 12 built-in agent profiles with
  configurable prompts/tools/budgets, evaluation and quality center, knowledge capture, rate limiting,
  evidence GC, backup/restore tooling and multi-instance leader locking for scheduled work.

## Known limitations

See the README [Status & limitations](https://github.com/EdouardRichard/EzTest/blob/main/README.md#status--limitations)
section. The most important ones for this preview:

1. Docker/Compose images and the Compose stack have never been built or started by the maintainers.
2. Resource credentials and browser `storageState` are stored **unencrypted** by design; only LLM
   credentials are encrypted. Treat the database and backups as sensitive, and expose EzTest only on a
   trusted network or behind your own TLS proxy.
3. Authentication is single-admin + ordinary users (no RBAC, no multi-tenancy); the browser token is
   stored in `sessionStorage`; CSP is report-only.
4. SSE broadcast, agent runners and rate limiting are in-process (single-instance). Only scheduling,
   autonomy and daily maintenance use a PostgreSQL leader lock.
5. Evidence GC deletes evidence files only; exports, attachments, report Markdown and orphan files are
   not cleaned automatically.
6. The web UI is Simplified Chinese only; no i18n switch exists in this preview.
7. AI behavior depends on the configured model and prompts; the recorded real-LLM acceptance is one run
   with one model, not a model matrix.

## Upgrade notes

This is the first preview, so there is no upgrade path from an earlier release. Migrations are
append-only and applied automatically at API startup; once you run a later version, roll back by
restoring a backup (database + all content directories), not by editing migration files. Keep
`EZTEST_SECRET_KEYS` separately from backups — losing it makes stored LLM credentials unrecoverable.
