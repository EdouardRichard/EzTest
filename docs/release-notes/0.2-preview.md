# EzTest 0.2-preview — release notes

**Release:** `v0.2.0-preview.1` · **Date:** 2026-11-02 · **License:** Apache-2.0

EzTest is a self-hosted, AI-driven, semi-autonomous end-to-end testing platform for web applications
and HTTP APIs. **0.2 is a complete rewrite of the platform core** built around a control plane: every
agent action is a `work_item` on a shared task board with leases and fencing, a reconciler keeps desired
and actual state aligned, and four agent teams plus a Version Steward drive clarification, design,
execution and delivery. Humans only clarify requirements, open design conversations and confirm cases.

> **Preview quality.** This is a single-team, self-hosted preview for evaluation — not a production
> release. It is not multi-tenant, not hardened, and the Docker/Compose stack has only been statically
> validated by the maintainers. Read *Verification status* and *Known limitations* below before relying
> on it.

## Quick start

```powershell
# Windows
Expand-Archive .\eztest-0.2.0-preview.1-windows-x64.zip -DestinationPath .\eztest
cd .\eztest\eztest-0.2.0-preview.1-windows-x64
.\init-config.ps1 -DatabaseUrl "postgres://eztest:<password>@localhost:5433/eztest?sslmode=disable"
.\start-eztest.ps1
```

```bash
# Linux
tar -xzf eztest-0.2.0-preview.1-linux-x64.tar.gz
cd eztest-0.2.0-preview.1-linux-x64
bash install-linux-deps.sh
bash init-config.sh --database-url "postgres://eztest:<password>@localhost:5433/eztest?sslmode=disable"
bash start-eztest.sh
```

Then open <http://localhost:6868> and sign in as the seeded administrator **`admin` / `admin123`** —
change that password immediately. Use `status-eztest.*` to inspect the stack, `stop-eztest.*` to stop it
and `smoke-test.*` to verify the installation end to end. The package includes the API, web UI,
Playwright executor and headless PDF renderer; PostgreSQL stays external.

Runtime configuration lives in the database settings center (four startup variables only:
`EZTEST_DATABASE_URL`, `EZTEST_API_PORT`, `EZTEST_WEB_PORT`, `EZTEST_EXECUTOR_PORT`). If you change the
executor or renderer token in the settings center, update the matching value in the package `.env` and
restart the stack.

Alternative deployments: Docker Compose (`deploy/docker-compose.yml`, statically validated only) and
running from source (Go 1.24.6 + Node 22 + pnpm 11 + PostgreSQL 17). See the README for details.

## What is in this release

- **Control plane and agent teams.** A single `work_item` task board (dedupe keys, leases, fencing
  epochs, retries), a reconciler that compares desired and actual state, persistent version × team
  channels, 19 task types and 14 built-in agent profiles.
- **Version and requirements workspace.** Multi-requirement versions, immutable requirement versions,
  clarification conversations, batch confirmation, relations and attachments.
- **Code-aware case design.** Read-only local Git indexing, evidence-checked AI code facts, impact
  analysis, and a reviewable scenario / case / step / assertion graph with requirement sources, SUT
  targets and code anchors. Human confirmation freezes immutable case versions; confirmed cases become
  the executable set automatically.
- **Multi-SUT autonomous execution.** One version can bind several systems; steps route per
  `version_sut_id`; browser contexts are created per `(version_sut, account_role)`. A separate
  Playwright executor drives real Chromium and HTTP, with optional read-only PostgreSQL and visual
  assertions, pause/resume and checkpoint recovery.
- **Evidence-bound delivery.** Four-state results with failure classification; content-addressed,
  immutable evidence; issue confirmation, merge, reopen and cross-wave recurrence; append-only report
  revisions with HTML and PDF output; an exploration chain from requirement to case, run, evidence,
  issue and report.
- **Platform.** Global knowledge with admin review, quality/evaluation center, agent center with prompt
  revisions and run observation, global search, todo drawer, unified content-ledger GC, event/audit
  retention, per-instance rate limiting, leader-based maintenance and multi-replica-safe API replicas.

Not verified or explicitly out of scope for this preview:

- **Docker / Compose** images and stack were never built or started by the maintainers — static
  validation only.
- **SLO, performance, load and security-audit evidence** was not produced for 0.2.
- **Long-execution coverage is partial:** the long 12-case / two-wave run, large tool-result spill and
  checkpoint recovery are not fully evidenced in the final acceptance run (approved as a preview
  waiver, tracked for a follow-up).
- **Hosted CI** is not a release gate for this preview.
- **AI behavior** depends on the configured model and prompts; the acceptance record is one model,
  one run — not a model matrix.

## Known limitations

1. **Not production-hardened.** Single-team, self-hosted preview: no RBAC, multi-tenancy, SSO, TLS
   termination or autoscaling; no production security or performance hardening. Expose it only on a
   trusted network.
2. **Credentials are stored in the database and masked in the UI, not encrypted at rest.** This
   includes LLM API keys, test-account passwords and browser session state by design. Treat the
   database and backups as sensitive. The fresh database seeds `admin` / `admin123` — change it
   immediately.
3. **Docker Compose is statically validated only** and has never been run by the maintainers.
4. **No SLO, performance or security-audit evidence** is claimed.
5. **Real-model behavior is non-deterministic.** Multi-turn clarification can occasionally produce
   duplicate requirement drafts; a model may emit free-text steps that cannot compile into executable
   actions.
6. **Visual assertions may end `inconclusive`.** There is no waiver endpoint yet, so auto-confirming
   every visual gap case can keep requirements from closing.
7. **Multi-replica boundaries.** Rate limiting is per instance (total = replicas × limit; default
   disabled), all API replicas must share one content directory, and SSE hubs and agent runners are
   in-process. No Redis/NATS/object storage, autoscaling or cross-region HA.
8. **No data migration from 0.1-preview.** 0.2 uses a new database schema. Migrations are append-only
   once applied; roll back by restoring a backup.
9. **Web UI is Simplified Chinese only** in this preview; there is no i18n layer.
10. **Scope:** PostgreSQL-only database assertions; functional testing of web UI and HTTP APIs only
    (no performance, security or mobile testing); no external ticket/CI/IM integrations.

## Upgrade notes

This release uses a new database schema and does not migrate data from the 0.1-preview. Create a new
database for 0.2. Migrations are append-only and applied automatically at API startup; do not edit
already-applied migration files. To roll back, restore a backup of the database and the content
directories together.
