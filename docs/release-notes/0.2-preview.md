# EzTest 0.2-preview — release notes

**Release:** `v0.2.0-preview.1` · **Date:** 2026-11-02 · **License:** Apache-2.0

EzTest is a self-hosted, AI-driven, semi-autonomous end-to-end testing platform for web applications and
HTTP APIs. **0.2 rebuilds the testing workflow and the human–AI interaction model.** A deterministic
control plane now orchestrates agent teams, and humans only do the three things that need judgment:

> clarify requirements in a conversation → open a design conversation → confirm the resulting cases

Everything else — scenario and case design, execution in a real browser and against HTTP APIs, failure
classification, issue handling, report rendering and driving the version to completion — is carried out
autonomously by the agent teams on top of the platform core.

## What's new in 0.2

- **Workflow rebuilt around a control plane.** Every agent action (including a chat turn) is a work item
  on a shared task board with priorities, dedupe keys, leases and fencing; a reconciler keeps desired
  and actual state aligned; four agent teams plus a Version Steward collaborate through persistent
  version × team channels, with no central orchestrating agent.
- **New human–AI interaction model.** Humans clarify requirements, open a design conversation and
  confirm cases (per case, scenario or requirement). Confirming cases automatically queues execution —
  there is no manual "start execution" step. A human-takeover card appears only when an automated login
  cannot be completed (2FA / captcha).
- **Version state is a projection, not a gate.** Versions move `initial → running → completed` and
  reopen automatically when a new goal appears; completed versions stay usable.
- **Multi-SUT by design.** One version can bind several systems; case steps route to a specific system,
  browser contexts are created per system × account role, and evidence/assertions stay scoped to the
  bound system.
- **Evidence-bound results.** Four-state verdicts (`passed` / `failed` / `blocked` / `inconclusive`) with
  failure classification; screenshots, console, network, API and visual evidence are content-addressed
  and immutable. Issues, exploration chain and append-only report revisions explain requirement → case
  → result → issue lineage.
- **HTML + PDF reports, knowledge and quality center.** Wave and version reports with revision history,
  HTML as the authoritative copy and PDF rendered by the bundled renderer; global knowledge reviewed by
  administrators; an agent center with profile, prompt revision and run observation; a quality center
  with evaluation metrics.
- **New workspace UI.** Eight global sections (Versions, Issues, Reports, Knowledge, Resources, Quality,
  Agent center, Settings) and eight version tabs (Overview, Requirements & clarification, Case design,
  Execution, Exploration chain, Issues, Reports, Code & changes), with global search and a todo drawer.
- **Minimal startup configuration.** The API reads four startup variables (database URL and API/web/
  executor ports); every other runtime setting lives in the database settings center and is managed from
  the UI.

## Installation and usage

**Prerequisites.** PostgreSQL 17 reachable from the machine; free ports 13333 (API), 6868 (web), 13336
(executor) and 13337 (PDF renderer); on Linux, the Chromium system libraries (installed once by the
bundled script).

```powershell
# Windows (PowerShell), after expanding the archive
cd eztest-0.2.0-preview.1-windows-x64
.\init-config.ps1 -DatabaseUrl "postgres://eztest:<password>@localhost:5433/eztest?sslmode=disable"
.\start-eztest.ps1
```

```bash
# Linux (x64), after extracting the archive
cd eztest-0.2.0-preview.1-linux-x64
bash install-linux-deps.sh
bash init-config.sh --database-url "postgres://eztest:<password>@localhost:5433/eztest?sslmode=disable"
bash start-eztest.sh
```

Then open <http://localhost:6868> and sign in as the seeded administrator **`admin` / `admin123`**;
change that password immediately after the first sign-in. `status-eztest.*` shows processes, health
probes and database status, `stop-eztest.*` stops the stack, and `smoke-test.*` runs an end-to-end
installation check.

**First-run setup in the UI.** Settings → LLM configuration: add an OpenAI-compatible provider and test
the connection. Resources: register systems under test, environments, pages, APIs, optional read-only
PostgreSQL targets, test accounts and local Git repositories. Then create a version, bind its systems
and add requirements to start the clarification → design → confirm → execution → delivery flow.

**Configuration.** Runtime settings (LLM credentials, executor/renderer URLs and tokens, limits,
retention, report templates) live in the database settings center and are managed from Settings. The
packaged `.env` only holds the startup values (database URL, ports and service tokens).

**Windows note.** The packaged `.ps1` scripts are not code-signed. If PowerShell refuses to load them
with "... is not digitally signed. You cannot run this script on the current system", allow the current
window only (`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`) and run the commands
normally, or invoke each script with
`powershell -NoProfile -ExecutionPolicy Bypass -File .\init-config.ps1 ...`. The Linux `.sh` scripts are
not affected.

## Upgrade notes

0.2 uses a new database schema. Create a new PostgreSQL database for this release; migrations are
append-only and applied automatically at API startup. Back up the database together with the package
`.data/` directory.

EzTest 0.2-preview：AI 驱动、半自主的 Web 与 HTTP API 端到端测试平台。

- **流程与人机交互重构：** 确定性控制面负责编排 Agent 团队；人只在三处介入——在对话中澄清需求、开启
  设计对话、确认产出的用例。确认用例后自动进入执行，无需手工"开始执行"；仅在 2FA/验证码等无法自动
  登录时出现人工接管卡片。
- **新执行与交付闭环：** 四团队 + Version Steward 通过任务板与版本×团队频道协作；版本状态是投影，
  出现新目标自动重开；原生支持多 SUT 与步骤级系统路由；结论绑定不可变证据，提供问题、探索链路与

  `smoke-test` 分别用于查看状态、停止与安装自检。
