# EzTest 用户手册（P8）

> 适用版本：P8（分支 `dev`，2026-10-29）。
> 读者：测试工程师、测试负责人、需要只读查看运行情况的项目成员。
> 相关文档：[部署指南](deployment.md)、[运维手册](operations.md)、[开发指南](development.md)、[P8 发布说明](release-notes/p8.md)。

EzTest 的主线是：**版本 → 需求/澄清 → 用例脑图/评审 → 执行批次 → 结果/证据 → 问题/报告 → 新需求继续中**。P8 在顶栏增加了版本切换器、全局搜索和待办中心，并把脑图放回版本详情 Tab；质量中心和知识库是 P8 新增页面。

## 1. 登录与基本界面

1. 打开 `http://<web-host>:6868/login`，使用管理员分配的账号登录。
2. 登录后进入侧边栏和顶栏组成的应用壳：
   - **侧边栏**：概览、版本、用例脑图、问题、报告、知识、代码仓、公共资源、Agent 中心、质量中心（仅管理员）、设置。
   - **顶栏**：移动端菜单（窄屏）、版本切换器、全局搜索（`Ctrl/Cmd+K` 或 `/`）、待办铃铛、主题切换、用户菜单。
3. token 存在浏览器 `sessionStorage`：关闭标签页/浏览器会话后需要重新登录；多个标签页各自持有会话。不要在公共电脑保持登录。

权限只有两层：**管理员**与**普通用户**。普通用户可读写版本/需求/文本用例/问题/报告等业务数据；管理员配置类页面（用户、LLM、Agent 配置、质量中心、审计、GC）仅管理员可见/可调用。

## 2. 版本切换器、全局搜索与待办

### 2.1 版本切换器（顶栏）

- 在任意页面点击顶栏的**切换版本**下拉：
  - 顶部“最近版本”最多 8 个（本机浏览器记录）；
  - 下方可搜索版本名称；选中后跳到该版本详情，并尽量保留当前 Tab（对象深链不保证跨版本保留）。
- 版本详情页的 10 个 Tab 都通过 `?tab=` 记住当前视图，刷新/分享链接可回到同一 Tab。
- 常用深链：
  - `?tab=requirements`（默认，需求与澄清）
  - `?tab=mindmap`（脑图 Tab；`&case=<id>` 选中节点）
  - `?tab=overview` / `sessions` / `exploration` / `broadcast` / `results`
  - `?tab=issues&issue=<id>`（问题详情）
  - `?tab=report&report=<id>`（指定报告 revision）
  - `?tab=code`（代码与变更）

### 2.2 全局搜索（`Ctrl/Cmd+K` 或 `/`）

- 输入至少 1 个字符、最多 100 个字符；结果按**版本 / 需求 / 用例 / 问题**分组，每组最多 5 条（可用 `limit` 调整到最多 20，但界面默认 5）。
- 键盘：`↑/↓` 在当前结果间移动，`Enter` 打开，`Esc` 关闭；点击结果也会跳转。
- 结果只包含标题、副标题、所属版本、状态与深链，不返回用例正文、证据正文或凭据。
- 如果某个上下文查询失败，搜索会返回其它分组并显示“部分结果”提示；不是“没有数据”。

### 2.3 待办中心（顶栏铃铛）

- 每 30 秒刷新一次，路由切换时立即刷新；数字是待办计数：
  - **待评审**：处于 `reviewing` 的版本（打开脑图 Tab）；所有登录用户可见。
  - **待接管**：等待人工接管的执行用例；仅管理员可见。
  - **待升级**：需要管理员决策的 gate；仅管理员可见。
  - 管理员还会看到**待审核知识**（草稿），数量上限 50，超出时显示“至少”提示。
- 点击条目跳到对应版本的 `?tab=mindmap` 或 `?tab=sessions`；加载失败时面板内可重试，不影响页面其它部分。

## 3. 版本、需求与澄清

### 3.1 新建版本

1. 进入 `/versions`，点击**新建版本**。
2. 填写：
   - **名称**（必填，最长 200 字符）；
   - **标识/label**（可选，短版本号，如 `v2.0`）；
   - **描述**（可选）；
   - **系统 / 环境 / 代码仓**（可选；环境必须属于所选系统）。
3. 版本创建后为 `draft`。资源绑定可稍后在“需求与澄清”工作台调整；未绑定资源的版本也能录需求/澄清，但不能执行。
4. 列表支持状态筛选与刷新；普通用户可创建版本（P3 无 per-user 授权）。

### 3.2 录入与确认需求

1. 进入版本详情，默认在**需求与澄清** Tab。
2. 左侧需求列表可新增、编辑、删除需求；需求字段包括标题、描述、优先级、验收标准等（以页面表单为准）。
3. 需求独立流转：`draft → clarified`。
   - 点击**确认**把需求置为已澄清；确认后编辑受限制。
   - 需要修改时先**重开**，改完再确认。
   - 新增/确认/重开需求**不会**自动改变版本文档状态。
4. 需求关系可维护 `depends_on`、`conflicts_with`、`overlaps`、`shares_scope`；关系图可辅助检查依赖。
5. 附件支持文本（`.txt/.md/.json/.yaml/.yml`）与图片（`.png/.jpg/.jpeg`）：单文件 ≤10 MiB、每需求 ≤10、每版本 ≤50；上传/下载需登录，删除为 best-effort。

### 3.3 澄清对话、问题与决策

- 右侧**澄清对话**可向澄清 Agent 提问；回答会形成问题（open/answered/dismissed）与决策（proposed/accepted/rejected）。
- 顶部按钮：
  - **开始澄清**：至少 1 条需求；创建澄清会话。
  - **进入设计**：要求需求已确认/无未澄清问题；若有未澄清项，会弹出二次确认，确认后仍可回到本 Tab 继续澄清。
- AI 不可用时，澄清/分析/侦察接口返回 503（`ai_unavailable`），人工录入、确认、关系、附件、决策路径仍可用。

## 4. 用例脑图与评审

### 4.1 脑图 Tab 与全屏

- 版本详情 **用例脑图** Tab 内嵌画布；也可打开全屏 `/versions/<id>/mindmap`。
- 两种入口共享同一份数据与编辑能力；全屏适合大图操作，Tab 适合边看需求边改。
- 脑图结构：场景/用例/步骤/断言/需求来源/代码锚点；节点/步骤/断言写入使用 revision 乐观并发，冲突时页面会提示刷新后重试。
- 评审通过后版本会冻结脑图基线（`baseline_frozen`）：之后脑图只读，不能直接改；需要新增/调整时走 P7 的补充/继续中流程，或在允许的状态下重新设计。

### 4.2 发起评审与处理发现

1. 在脑图页点击**发起评审**，选择评审 Agent/范围。
2. 评审结果为 findings（按严重级 blocker/major/minor/info 分组）；blocker 必须处理/确认。
3. **批准**会冻结基线并进入执行阶段；**驳回**需要填写原因，版本回到可编辑状态。
4. 基线冻结后，脑图页显示只读标识；执行批次使用冻结的用例快照，保证可复现。

### 4.3 导出

- 脑图支持 Markdown、Mermaid、OPML 导出；PNG 由前端画布生成。
- 导出文件下载需要登录；同一冻结基线 + 格式的导出可复用（不再重复写文件）。
- 导出内容来自当前冻结快照，不包含凭据、Session 原文或 prompt。

## 5. 执行、暂停/恢复与人工接管

### 5.1 开始执行

1. 版本进入 `executing` 且已有冻结基线后，顶部出现**开始执行**。
2. 选择要执行的用例（默认全部；也可按需求/状态筛选），创建批次。
3. 执行由独立 Playwright executor 完成；页面通过 SSE 实时刷新会话、结果、证据。
4. 一个版本同时只允许一个活跃批次（`batch_active`）；批次有 `baseline` / `incremental` / `supplement` 等类型（P7 起）。

### 5.2 暂停与恢复

- 顶部**暂停**支持两种模式：
  - **优雅暂停**：等待当前步骤完成，不再派发新用例；运行中的用例回到 pending。
  - **立即暂停**：立即取消 Agent run/执行器动作，未完成步骤标记中断；恢复时先 cleanup 再继续。
- 已暂停批次顶部显示横幅与**恢复执行**；恢复会从暂停点继续，不重跑已完成用例。
- `paused/pause_mode/batch_no` 是 P6 兼容字段，可能在 API DTO 中保持 snake_case；页面已统一处理。

### 5.3 执行会话与实时播报

- **执行会话** Tab：按 Agent/用例分组的 transcript（思考折叠、工具调用折叠、断言期望 vs 实际、证据入口）；支持过滤/搜索；断线显示“重连中”而不是“没有消息”。
- **实时播报** Tab：版本事件流倒序，异常置顶；可按事件类型/Agent 过滤，点击深链到用例/证据。
- **探索链路** Tab：需求 → 用例 → 最新结果 → 问题的只读聚合图；支持需求/状态/仅异常/AI 补充/重新校验筛选、节点抽屉、MiniMap、图例、跟随执行；节点过多时按预算截断并显示顶部横幅（计数仍为截断前真实值）。

### 5.4 结果、证据与人工接管

- **结果与证据** Tab：用例结果表（失败/阻塞置顶）、步骤/断言展开、终态重跑。
- 证据查看器按 `kind` 渲染截图、HTTP 请求/响应、console/日志等；显示 sha256/大小/MIME，不显示文件系统路径；支持前后证据对比（P8）。
- 需要人工处理时，会话内出现**需要人工接管**卡片：管理员可完成接管；普通用户只读可见。接管完成后可继续执行。

### 5.5 新需求与“继续中”

- 版本完成后再加需求，可使用**新增需求**进入继续中流程：创建增量批次，只执行受影响/新增用例；页面顶部显示“继续中（第 N 批）”。
- 补全批次（`supplement`）由 AI 提出新用例，需人工接受/拒绝后才进入执行；自动补全批次受上限保护。

## 6. 问题与报告

### 6.1 问题

- 版本内**问题** Tab：列表支持状态/严重级/分类/批次筛选与标题搜索；详情展示复现步骤、期望/实际、证据、代码锚点、环境/Session 指纹。
- 问题状态：`open` → `confirmed` / `dismissed`（P8 不做重开/合并）。
- 确认/驳回使用 revision CAS；驳回必须填写原因。
- 深链：`?tab=issues&issue=<id>`；全局只读中心 `/issues` 可跳回版本。

### 6.2 报告

- 版本内**报告** Tab：按批次选择报告，查看最新 revision；可切换到历史 revision（`?report=<id>`）。
- 内容：范围、执行摘要、需求覆盖矩阵、用例结果、问题、风险/结论、附录；Markdown 可导出（带 `X-Content-SHA256`）。
- 发布/重新生成：
  - 报告发布后若证据/失败分类计数变化，会被标记 **stale**；页面显示横幅，可“重新生成”追加 revision（旧 revision 保留）。
  - **升级到 P8 后旧报告可能首次读取时 stale 一次**，原因是指纹口径扩展；内容不丢，重新生成即可。
- 报告快照包含批次回退标记（`baseFallbackReason` / `historyRewritten`）；老 revision 显示“未记录”。
- 全局只读中心 `/reports` 可跳回版本报告 Tab。

## 7. 代码与变更、事实修正

### 7.1 代码仓

- `/code-repos`：管理员可新建/编辑/删除本地 Git 代码仓，填写 `localPath`、固定分支、include/exclude；保存时做只读 Git 校验。
- 普通用户只读列表，可查看当前 commit 与索引状态。
- 代码仓路径必须是 API 进程可读的本地 Git 工作树；容器部署时由运维只读挂载（见 [部署指南](deployment.md#代码仓只读挂载)）。

### 7.2 代码与变更 Tab

- 展示批次时间线（base/head、变更文件数、受影响用例、未映射数）、变更文件/实体、受影响用例、未映射原因。
- 变更预览优先读持久化的 `version_change` 快照，缺失时才回退读时派生；历史批次可追溯。
- 本 Tab 只读展示代码内容窗口/diff 片段，不回传整仓或凭据。

### 7.3 事实人工修正与质量区块

- 对 AI 产出的事实可做**正确/不正确**人工修正（可选备注）；修正结果进入质量聚合。
- 代码仓质量区块展示证据通过率、无效事实、置信度分布、人工复核计数、最新评测的影响精确率/召回率、缓存命中率；缺失数据源显示“不可用/无数据”，不伪造指标。

## 8. 知识沉淀

### 8.1 提交草稿（版本内）

1. 打开版本详情 → **总览** Tab，底部“版本知识”面板。
2. 选择类型：`pattern`（模式）/ `pitfall`（陷阱）/ `decision`（决策）/ `case_idea`（用例灵感）；选择置信度 high/medium/low。
3. 填写标题（≤300 字符）与正文（≤16 KiB），可加标签（≤20 个、每个 ≤50 字符）和来源引用（需求/用例/问题/证据，最多 20 个）。
4. 点击**提交草稿**；草稿状态为 `draft`，等待管理员审核。

### 8.2 审核（管理员）

- 管理员在 `/knowledge` 点击**审核队列**，或通过 `/knowledge?review=<id>` 深链打开审核抽屉。
- 审核队列只显示 `draft`；**批准**后条目进入全局已批准知识库；**驳回**必须填写原因。
- 普通用户在版本内只能看到已批准条目 + 自己创建的草稿/驳回条目；全局 `/knowledge` 默认只读已批准。
- 管理员可编辑草稿（创建者也可编辑自己的草稿）；编辑使用 revision CAS，冲突需刷新重试。

### 8.3 注入与追溯

- 已批准知识会在本版本的**澄清/分析/侦察**与**脑图设计**运行前注入提示词；`review`/`data_plan` 运行不注入。
- 注入受条数与字节预算限制（`EZTEST_KNOWLEDGE_MAX_INJECT` 默认 5，`EZTEST_KNOWLEDGE_MAX_BYTES` 默认 4096）；超出会截断并记录 `knowledge_truncated` 警告。
- 运行结果/统计中记录 `knowledgeRefs`（条目 ID 列表），可在运行详情/日志中追溯用了哪些知识；草稿/驳回不会注入。
- P8 只做版本内闭环；跨版本检索/复用/治理是 P9 候选。

## 9. 质量中心（管理员）

- `/quality`：展示评测历史与最新一次 run；普通用户看到“仅管理员可查看评测”，API 也返回 403。
- 指标（6 项，页面按 5 组展示，影响召回/精确同组）：
  - `design_coverage` 设计覆盖率
  - `impact_recall` 影响召回率
  - `impact_precision` 影响精确率
  - `classification_accuracy` 失败分类准确率
  - `issue_false_positive_rate` 问题误报率
  - `supplement_hit_rate` 补充命中率
- 每项显示值、阈值、是否通过；确定性轨道有基线回归规则（任一指标比基线差 >0.05 失败），真实 LLM 轨道只报告。
- 页面只读，数据由 `scripts/eval.ps1` 通过管理员 API 写入；运行命令与语料维护见 [开发指南](development.md#4-评测eval) 与仓库根 `eval/README.md`。

## 10. Agent 中心

- `/agents`：
  - **角色目录**：13 个逻辑角色（澄清、需求分析、上下文侦察、应用探索、测试设计、设计评审、数据/前置规划、执行、补全、失败分析、问题整理、报告整理、知识沉淀）；显示阶段、模式、profile、模型、工具、运行统计。
  - **运行观察**：按角色/状态过滤会话，打开只读 transcript（管理员可进“配置与控制台”）。
  - **质量指标**：最新评测的指标/阈值（无数据时显示空，不编造）。
- 普通用户只读角色目录、运行观察与质量指标；管理员可修改 P1 profile/提示词/工具白名单，并进入控制台。
- 报告整理与知识沉淀没有独立 profile，页面明确标注“确定性生成/人工审核”，不要期待可配置提示词。

## 11. 设置与审计（管理员）

`/settings` 五个 Tab：

| Tab | 用途 |
|---|---|
| 用户 | 创建普通用户、启用/禁用、重置密码（撤销其 token）。 |
| LLM | 配置 base URL/模型/Key/headers、模型目录刷新、连通性/多模态测试。Key 不回显。 |
| SSE 测试 | 发布测试事件、验证事件流/断线回放。仅建议开发/测试环境使用。 |
| 基础配置 | 只读展示生效的限流/GC 阈值与数据库/executor 等运行信息；GC dry-run 预览与执行（执行需 `EZTEST_GC_ENABLED=true` 且二次确认）。 |
| 审计日志 | 按 actor/action/时间过滤，导出已加载条目为 CSV/Markdown。 |

审计日志不记录密码、token、LLM Key、storageState、SQL 结果、证据正文或 prompt；GC 审计只含计数/阈值/操作者。

## 12. 当前不提供的能力（避免误解）

- **视觉断言**（截图基线/像素差异/基线审批）：代码已有部分实现（迁移、编辑/审批服务、executor 比对、查看器），但 API 装配与 execution agent 执行入口尚未接线；当前页面可能显示相关编辑控件，实际保存/审批/执行不可用。不要把它当作已交付能力，后续接线完成后再更新本手册。
- 报告 PDF/HTML 导出、问题重开/合并、跨版本知识库、多用户协作/审批、非 PostgreSQL 目标库：P9 候选或未排期。
- 多实例编排：P8 只有单活锁与单实例 SSE/Agent runner；普通使用无需关心，但不要假设多副本共享实时连接。
- 外部工单/CI/IM 集成、多租户/RBAC：未实现。
- 证据 GC 只清执行证据文件；导出、附件、报告 Markdown、孤儿文件不会自动清理。
- 没有“管理员 impersonate 普通用户”能力；排查权限请用普通账号复现。

## 13. 常见问题

| 现象 | 处理 |
|---|---|
| 登录后提示“无法连接 API” | 确认 Web 的 `NEXT_PUBLIC_API_BASE_URL` 与 API 可达；容器部署检查反代。 |
| 搜索没有结果 | 关键字至少 1 字符；某类无结果不代表全部失败，注意“部分结果”提示；无权限数据不会返回。 |
| 待办为空但确有版本待评审 | 待评审由版本状态驱动；确认版本处于 `reviewing`，管理员才看得到接管/gate。 |
| 脑图只读/无法编辑 | 基线已冻结；走补充/继续中或在允许状态下重新设计。 |
| 开始执行按钮不可用 | 版本未进入 `executing`、未冻结基线、无用例，或已有活跃批次。 |
| 报告 stale | 证据/失败分类变化或升级后首次读取；重新生成追加 revision，不要手改数据库。 |
| 知识没被注入 | 仅 approved 生效；检查预算、`knowledgeRefs`、是否在澄清/设计运行前提交。 |
| 质量中心没数据 | 需要先运行 `scripts/eval.ps1` 写入；普通用户无权查看。 |
| 审计里看不到某操作 | 该路径可能未接审计；以安全审计覆盖矩阵为准，反馈给管理员。 |
| 429 限流 | 等待 `Retry-After` 或让管理员调整阈值；多副本时限额按实例合计。 |

更多运维/部署排障见 [运维手册](operations.md#日志与故障处理) 与 [部署指南](deployment.md#9-常见故障)。
