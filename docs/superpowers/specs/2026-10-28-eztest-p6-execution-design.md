## 1. 目标与非目标

### 1.1 目标

交付 `implementation-phases.md` §2-P6 的垂直切片，达到 M6「用例可执行」：

1. **领域与引擎**：RunBatch / CaseRun / StepResult / AssertionResult / Evidence / RunEvent；批次计划、用例调度、并发上限、Session/账号资源冲突排队、步骤检查点。
2. **真实执行**：独立 Node/Playwright 执行器（A′）；浏览器导航/DOM-A11y/点击输入/截图/storageState、HTTP/API、控制台/网络日志、下载；所有请求受环境 `allowed_hosts` 约束。
3. **暂停/恢复**：`paused` 独立布尔；优雅/立即两种模式；步骤检查点续跑；interrupted 用例恢复前 cleanup/seed；重启后状态正确。
4. **Session 补齐**：最小表单自动登录 + 注入 + 失效重取一次 + 人工接管（表单 A：人工导入 storageState 后自动继续）。
5. **证据**：截图/HTTP 交换/日志/下载，文件系统存储（D30）+ sha256 + 不可变 + 引用可回溯。
6. **结果**：四态 passed/failed/blocked/inconclusive（另有 skipped/interrupted 过程态）；失败分类 v1（application/environment/session/model/case；flaky 为派生标记）且「应用缺陷」只来自有证据的断言失败。
7. **实时与前端**：执行会话、探索链路、实时播报、结果与证据、报告（Batch 1）五个 Tab；顶栏暂停/恢复、接管卡；SSE 实时。
8. **验收**：自动化门禁 + 真实 LLM 验收 + Lead 代用户执行的真实人工验收。

### 1.2 非目标（P6 明确不做）

AI 补全、失败分析 Agent、问题（issue）、完整报告（revision/stale/批次差异/持久化报告版本）、继续中（continuing）与增量批次、视觉断言、Mock/测试数据夹具工具、多版本并行执行、跨用例语义依赖、权限探测配方（ProbeRecipe）、MCP 工具生态。**DB 断言（只读）归 P7**（本轮确认，见 §14）；其余逐项后续归属见 §14 去留表。

### 1.3 本轮的共同理解（用户已确认）

- 浏览器执行采用 **A′**：独立 Node/Playwright 长驻执行器，Go 只编排；不照搬 ARTEX 的 per-run MCP/stdio 接法（ARTEX 只作为「Node 拥有浏览器、Go 编排」的同源证据）。
- 执行控制采用 **方案 1**：引擎确定性 + 执行 Agent 结构化提交 + 服务端校验。
- Session 自动登录只做 **最小 password 表单 + 头注入**；MFA/验证码/SSO 一律转人工接管。
- 真实执行与人工验收的被测目标是 **仓库内 fixture**（扩展为带登录的 Web + API 双目标）。
- **DB 断言（只读）明确归 P7**（P6 遇 db 断言只能 inconclusive，绝不假通过）；P7 规格需补目标库连接配置与只读凭据面。
- 成功标准 = §2-P6 四条退出标准 + 真实人工验收全程通过；不以「脚本绿」代替人工判定。

```sql
CREATE TABLE IF NOT EXISTS run_batch (
  id                     BIGINT NOT NULL,
  version_id             BIGINT NOT NULL,
  batch_no               INT NOT NULL CHECK (batch_no >= 1),
  status                 TEXT NOT NULL DEFAULT 'planned'
                           CHECK (status IN ('planned','running','done','failed','cancelled')),
  paused                 BOOLEAN NOT NULL DEFAULT false,
  pause_mode             TEXT NOT NULL DEFAULT 'graceful'
                           CHECK (pause_mode IN ('graceful','immediate')),
  pause_reason           TEXT NOT NULL DEFAULT '',
  baseline_hash          TEXT NOT NULL CHECK (baseline_hash ~ '^[0-9a-f]{64}$'),
  code_baseline_commit   TEXT CHECK (code_baseline_commit IS NULL
                           OR code_baseline_commit ~ '^[0-9a-f]{40}$'),
  head_commit            TEXT CHECK (head_commit IS NULL
                           OR head_commit ~ '^[0-9a-f]{40}$'),
  case_count             INT NOT NULL DEFAULT 0 CHECK (case_count >= 0),
  passed_count           INT NOT NULL DEFAULT 0 CHECK (passed_count >= 0),
  failed_count           INT NOT NULL DEFAULT 0 CHECK (failed_count >= 0),
  blocked_count          INT NOT NULL DEFAULT 0 CHECK (blocked_count >= 0),
  inconclusive_count     INT NOT NULL DEFAULT 0 CHECK (inconclusive_count >= 0),
  skipped_count          INT NOT NULL DEFAULT 0 CHECK (skipped_count >= 0),
  interrupted_count      INT NOT NULL DEFAULT 0 CHECK (interrupted_count >= 0),
  created_by             BIGINT NOT NULL,
  started_at             TIMESTAMPTZ,
  finished_at            TIMESTAMPTZ,
  failure_reason         TEXT NOT NULL DEFAULT '',
  created_at             TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at             TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT pk_run_batch PRIMARY KEY (id),
  CONSTRAINT uk_run_batch_version_no UNIQUE (version_id, batch_no),
  CONSTRAINT ck_run_batch_counts CHECK (
    passed_count + failed_count + blocked_count + inconclusive_count
    + skipped_count + interrupted_count <= case_count)
);
-- One active batch per version; paused keeps status='running' so it stays active.
CREATE UNIQUE INDEX IF NOT EXISTS uk_run_batch_active
  ON run_batch(version_id) WHERE status IN ('planned','running');
CREATE INDEX IF NOT EXISTS idx_run_batch_version_created
  ON run_batch(version_id, created_at DESC, id DESC);

CREATE TABLE IF NOT EXISTS case_run (
  id                     BIGINT NOT NULL,
  batch_id               BIGINT NOT NULL REFERENCES run_batch(id) ON DELETE CASCADE,
  version_id             BIGINT NOT NULL,
  case_node_id           BIGINT NOT NULL,
  case_revision          INT NOT NULL CHECK (case_revision >= 1),
  case_hash              TEXT NOT NULL CHECK (case_hash ~ '^[0-9a-f]{64}$'),
  case_snapshot          JSONB NOT NULL,
  attempt                INT NOT NULL DEFAULT 1 CHECK (attempt >= 1),
  status                 TEXT NOT NULL DEFAULT 'pending'
                           CHECK (status IN ('pending','running','passed','failed',
                                             'blocked','inconclusive','skipped','interrupted')),
  failure_class          TEXT CHECK (failure_class IN
                           ('application','environment','session','model','case')),
  failure_reason         TEXT NOT NULL DEFAULT '',
  summary                TEXT NOT NULL DEFAULT '',
  session_id             BIGINT,
  session_snapshot_id    BIGINT,
  agent_session_id       BIGINT,
  agent_run_id           BIGINT,
  retry_of_case_run_id   BIGINT,
  cleanup_required       BOOLEAN NOT NULL DEFAULT false,
  interrupted_step_seq   INT CHECK (interrupted_step_seq IS NULL OR interrupted_step_seq >= 1),
  started_at             TIMESTAMPTZ,
  finished_at            TIMESTAMPTZ,
  duration_ms            BIGINT NOT NULL DEFAULT 0 CHECK (duration_ms >= 0),
  created_at             TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at             TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT pk_case_run PRIMARY KEY (id),
  CONSTRAINT uk_case_run_batch_case_attempt UNIQUE (batch_id, case_node_id, attempt),
  CONSTRAINT ck_case_run_failure_class CHECK (
    failure_class IS NULL OR status IN ('failed','blocked','inconclusive'))
);
CREATE INDEX IF NOT EXISTS idx_case_run_batch_status
  ON case_run(batch_id, status, id);
CREATE INDEX IF NOT EXISTS idx_case_run_version_status
  ON case_run(version_id, status, id);

CREATE TABLE IF NOT EXISTS step_result (
  id             BIGINT NOT NULL,
  batch_id       BIGINT NOT NULL REFERENCES run_batch(id) ON DELETE CASCADE,
  case_run_id    BIGINT NOT NULL REFERENCES case_run(id) ON DELETE CASCADE,
  seq            INT NOT NULL CHECK (seq >= 1),
  action         TEXT NOT NULL DEFAULT '',
  expected       TEXT NOT NULL DEFAULT '',
  actual         TEXT NOT NULL DEFAULT '',
  status         TEXT NOT NULL DEFAULT 'pending'
                   CHECK (status IN ('pending','running','passed','failed','interrupted')),
  evidence_count INT NOT NULL DEFAULT 0 CHECK (evidence_count >= 0),
  started_at     TIMESTAMPTZ,
  finished_at    TIMESTAMPTZ,
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT pk_step_result PRIMARY KEY (id),
  CONSTRAINT uk_step_result_case_seq UNIQUE (case_run_id, seq)
);
CREATE INDEX IF NOT EXISTS idx_step_result_case ON step_result(case_run_id, seq);

CREATE TABLE IF NOT EXISTS assertion_result (
  id              BIGINT NOT NULL,
  batch_id        BIGINT NOT NULL REFERENCES run_batch(id) ON DELETE CASCADE,
  case_run_id     BIGINT NOT NULL REFERENCES case_run(id) ON DELETE CASCADE,
  step_result_id  BIGINT REFERENCES step_result(id) ON DELETE SET NULL,
  assertion_id    BIGINT NOT NULL,
  kind            TEXT NOT NULL CHECK (kind IN ('ui','api','db','text')),
  target          TEXT NOT NULL DEFAULT '',
  expected        TEXT NOT NULL DEFAULT '',
  actual          TEXT NOT NULL DEFAULT '',
  verdict         TEXT NOT NULL DEFAULT 'not_run'
                    CHECK (verdict IN ('passed','failed','not_run')),
  failure_reason  TEXT NOT NULL DEFAULT '',
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT pk_assertion_result PRIMARY KEY (id),
  CONSTRAINT uk_assertion_result_case_assertion UNIQUE (case_run_id, assertion_id)
);
CREATE INDEX IF NOT EXISTS idx_assertion_result_case ON assertion_result(case_run_id, id);

CREATE TABLE IF NOT EXISTS evidence (
  id             BIGINT NOT NULL,
  batch_id       BIGINT NOT NULL REFERENCES run_batch(id) ON DELETE CASCADE,
  case_run_id    BIGINT REFERENCES case_run(id) ON DELETE CASCADE,
  step_result_id BIGINT REFERENCES step_result(id) ON DELETE SET NULL,
  kind           TEXT NOT NULL CHECK (kind IN
                   ('screenshot','http_exchange','console_log','network_log','download')),
  path           TEXT NOT NULL CHECK (path <> ''),
  sha256         TEXT NOT NULL CHECK (sha256 ~ '^[0-9a-f]{64}$'),
  size_bytes     BIGINT NOT NULL CHECK (size_bytes > 0),
  mime           TEXT NOT NULL DEFAULT '',
  metadata       JSONB NOT NULL DEFAULT '{}'::jsonb,
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT pk_evidence PRIMARY KEY (id)
);
CREATE INDEX IF NOT EXISTS idx_evidence_case_created ON evidence(case_run_id, created_at, id);
CREATE INDEX IF NOT EXISTS idx_evidence_batch_created ON evidence(batch_id, created_at, id);

CREATE TABLE IF NOT EXISTS evidence_ref (
  evidence_id BIGINT NOT NULL REFERENCES evidence(id) ON DELETE CASCADE,
  ref_kind    TEXT NOT NULL CHECK (ref_kind IN
                ('step_result','assertion_result','case_run','batch','report','issue')),
  ref_id      BIGINT NOT NULL,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT pk_evidence_ref PRIMARY KEY (evidence_id, ref_kind, ref_id)
);
CREATE INDEX IF NOT EXISTS idx_evidence_ref_target ON evidence_ref(ref_kind, ref_id);
```

> `systems`/`account_system_accesses` 已按 D34 改名为单数 `system`/`account_system_access`；`idx_account_system_accesses_login_flow` 是已应用迁移的冻结索引名，不改名（与 `resource_0006_auth_flows.sql` 一致）。

- `definition` 最小 schema（`kind=form`）：

```json
{
  "login_url": "http://127.0.0.1:13335/p6/login",
  "username_selector": "#username",
  "password_selector": "#password",
  "submit_selector": "button[type=submit]",
  "success": {"url_contains": "/p6/home"},
  "failure": {
    "mfa_selector": "#mfa",
    "captcha_selector": "#captcha",
    "invalid_selector": ".login-error"
  },
  "timeout_ms": 20000
}
```

- `success` 二选一（`url_contains` 或 `selector`）；`failure` 可省略；`timeout_ms` 5000–60000。服务端保存时校验必填与合法 URL（http/https）。
- `session.storage_state` 扩展保留每个 origin 的 `sessionStorage`（加法式；旧状态不受影响）。

- 不改任何已应用迁移的字段/约束/索引名。

### 4.2 跨上下文端口（execution/application 定义，infrastructure 实现）

```go
type VersionPort interface {
    GetVersion(ctx context.Context, versionID int64) (VersionRef, error)
    MarkPaused(ctx context.Context, versionID int64, paused bool, mode, reason string, actor int64) error
    AllocateBatchNo(ctx context.Context, versionID int64) (int, error)
    ReleaseBatchNo(ctx context.Context, versionID int64, allocated int) error
    SetBatchNo(ctx context.Context, versionID int64, batchNo int, actor int64) error
    CompleteExecution(ctx context.Context, versionID int64, actorID int64) error
}

type MindmapPort interface {
    Baseline(ctx context.Context, versionID int64) (BaselineRef, error) // hash, commit, case ids
    SnapshotCases(ctx context.Context, versionID int64, caseIDs []int64) ([]CaseSnapshotSourceView, error)
    MarkExecuted(ctx context.Context, versionID int64, caseNodeIDs []int64) error
}

type SessionPort interface {
    Acquire(ctx context.Context, envID, systemID int64, holder string, ttl time.Duration) (SessionRef, error)
    Release(ctx context.Context, sessionID int64, holder, reason string) error
    MarkInvalid(ctx context.Context, sessionID int64, reason string) error
    PendingTakeover(ctx context.Context, sessionID int64) (*TakeoverRef, error)

type AgentRuntimePort interface {
    EnsureProfile(ctx context.Context) error
    StartCaseRun(ctx context.Context, req CaseRunRequest) (AgentRunRef, error)
    CancelRun(ctx context.Context, sessionID int64) error
    GetRun(ctx context.Context, sessionID int64) (AgentRunState, error)
    ListSessions(ctx context.Context, versionID int64) ([]AgentSessionRef, error)
}

type EventPublisher interface { Publish(ctx context.Context, ev Event) error }
type EvidenceStore interface {
    Write(ctx context.Context, rel string, data []byte) (path, sha256 string, size int64, err error)

}
type BrowserExecutor interface {
    Health(ctx context.Context) error
    NewContext(ctx context.Context, req ContextSpec) (ContextRef, error)
    Action(ctx context.Context, ref ContextRef, action Action) (ActionResult, error)
    Cancel(ctx context.Context, ref ContextRef) error
    Close(ctx context.Context, ref ContextRef) error
```

- `SessionPort.Acquire` 内部完成「选会话 → 租约 → 必要时自动登录 → needs_manual/takeover」；execution 不直接操作 Session 状态机。

- `mindmap/application` 新增 `ExecutionSnapshot` 查询与 `MarkExecuted`（只允许 `reviewed→executed`，不触碰基线只读规则）。

### 4.3 请求流

```text
POST batches
  → 校验 version executing / 无活跃批次 / 基线存在
  → 读 mindmap baseline + case snapshots（事务外只读）
  → 事务：run_batch + case_run*；version.batch_no 在插入前经 `AllocateBatchNo` 原子分配，插入失败用 `ReleaseBatchNo` 补偿（号段单调不保证连续）
  → 事件 batch.created/started
  → 调度器（2s tick + 触发）派发 pending
      → 取 Session（租约）→ 创建执行器 context（注入 storageState）
      → 创建 agent session/run（activity_channel=version:{id}）
      → Agent 调工具：case_context/browser.*/http.request/step_record/assertion_record/case_finish
      → 每次提交由引擎校验并落库 + 发事件
  → 用例终态 → 释放租约/关闭 context → 批次聚合
  → 全终态：batch done、version completed、batch.finished
```

## 5. 核心规则

### 5.1 批次前置门禁

| 条件 | 失败 reason |
|---|---|
| 版本存在且当前用户可见 | 404 |
| `version.status='executing'` | 409 `version_not_executable` |
| 版本绑定 system+environment | 409 `environment_required` |
| 存在 `case_baseline` | 409 `baseline_required` |
| 无活跃批次（planned/running） | 409 `batch_active` |
| 基线用例数 ≥1 且 ≤ `EZTEST_EXEC_MAX_CASES_PER_BATCH` | 409 `no_cases` / 422 `too_many_cases` |
| `baseline_hash` 与当前基线一致 | 409 `baseline_changed` |
| 执行器健康 | 503 `executor_unavailable` |
| 指定 `caseIds` 均为本版本基线内 case | 422 `invalid_case_ids` |

### 5.2 用例快照与基线一致性

- 快照结构（`case_snapshot`）：

```json
{
  "node": {"id":"...","title":"...","priority":"P1","preconditions":"...","test_data":{}},
  "steps": [{"seq":1,"action":"...","expected":"...","data":{}}],
  "assertions": [{"id":"...","step_seq":1,"kind":"ui","target":"...","expression":"...","expected":"..."}],
  "sources": [{"requirement_id":"..."}],
  "graph_hash": "...",
  "captured_at": "..."
}
```

- `case_hash` = 对规范化快照 JSON 的 sha256（与 P5 `CanonicalGraphHash` 同风格，但只覆盖该用例）；批次创建后快照不可变。
- 批次创建时复核 `case_baseline.graph_hash`；不一致 → 409，不创建半批数据。
- 执行不会修改脑图内容；通过 `MindmapPort.MarkExecuted` 将 `case_node.status` 从 `reviewed` 标为 `executed`（失败/阻塞同样标 executed，结果在 CaseRun 上）。

### 5.3 调度、并发与资源冲突

- `EZTEST_EXEC_MAX_CONCURRENT_CASES` 默认 3（1–8）；每用例 1 agent run + 1 context + 1 session 租约。
- 派发顺序：优先级 `P0>P1>P2>P3`，再按 `case_node_id` 升序；`pending` 中重试 attempt 优先于首次？**不**，统一按上述确定性排序，避免饥饿与不可复现。
- **Session 选择**：`state=valid`、未过期、租约空闲、`access.concurrency_limit` 未满；按 `last_used_at` 升序（最久未用优先），并列按 token 字典序构造。
- 无会话：触发自动登录（§5.9）；仍无 → 该用例 `blocked(session)`（reason=`no_session`，提示配置/导入会话；无 session 行时不能建接管卡）；若自动登录进入 MFA/验证码/审批 → `blocked(session)` + 接管卡。其余用例继续。
- 同一 Session 冲突 → 用例留在 `pending` 等待，不计失败；等待期间不占 agent run。
- 跨用例语义依赖不在 P6 建模（P5 无字段）；「依赖」= 步骤串行 + 资源互斥 + 恢复顺序。
- 调度器单实例（P6 单进程）；多实例部署需分布式租约（P8）。

### 5.4 暂停 / 恢复 / 检查点 / 恢复

| 操作 | 规则 |
|---|---|
| 优雅暂停 | 置 `run_batch.paused=true, pause_mode='graceful'`、`version.paused=true`；停止派发；对运行中用例：完成当前步骤后取消 Agent run、`case_run.status='pending'`、保留已完成 `step_result`；释放租约/context；发 `run.paused` |
| 立即暂停 | 置 paused/immediate；`CancelRun` + executor `cancel`；在飞步骤置 `interrupted`；`case_run.status='interrupted'`、`cleanup_required=true`；释放租约/context；发 `run.paused` |
| 恢复 | 仅 `paused=true` 可恢复；清 paused（批次与版本）；`pending` 从检查点续跑；`interrupted` 生成**同 attempt 的续跑**（不新建 attempt），先 cleanup/seed 再继续；发 `batch.resumed`/`run.resumed` |
| 重复暂停/恢复 | 409 `already_paused` / `not_paused`；批次终态 409 `batch_finished` |
| 取消 | `pending → skipped`；`running → interrupted`（立即中断 + `cleanup_required=true`）；批次 `cancelled`；释放租约/context；发 `batch.finished`；版本保持 `executing`（可重新建批） |
| 暂停期间 | 可查看事件/证据/报告；禁止建新批次（batch_active 仍占位）；新增需求（P3）不受影响 |
| 崩溃/重启 | Boot 恢复（有序幂等 CAS，非单事务）：`running case_run → interrupted(reason=restart)`、`cleanup_required=true`、批次 `paused=true, immediate, reason=restart`、版本 `paused=true`、释放残留租约；P1 已把 running agent run 标 interrupted；事件 `run.paused`+`batch.paused`。**不自动拉起浏览器**，由用户恢复 |
| 检查点 | 即已完成 `step_result`；恢复提示包含「已完成步骤摘要 + 剩余步骤 + cleanup 要求」；未完成步骤不伪造结果 |
| 恢复失败 | 若 cleanup/seed 失败 → `blocked(environment)` 或 `inconclusive(case)`（按错误码），批次继续 |

- 优雅暂停等待当前步骤的边界：引擎在工具调用之间检查 `paused`；不打断已落库的 `step_record`。
- 立即暂停的 `interrupted_step_seq` 记录被中断的步骤号，供 UI 展示与恢复定位。
- Boot 恢复以**有序幂等 CAS** 实现（`running→interrupted` → 释放租约 → 刷新计数 → 批次 paused → 版本镜像 → 发事件）；storage ports 不暴露跨仓储事务，因此不做单事务，任一步中途崩溃由下一次 pass 补齐（Lead 已接受该偏离，恢复实现见 `backend/internal/execution/application/recovery.go`）。

### 5.5 执行 Agent 协议

- 每条用例一个 Agent session（`activity_channel=version:{id}`）；profile `execution-agent`；模型沿用默认 LLM 配置；`run_seconds` 与 `max_turns` 由 profile 配置。
- 预算：默认 80 次工具调用 / 15 分钟 / 30 轮（`EZTEST_EXEC_MAX_TOOL_CALLS`、`EZTEST_EXEC_CASE_TIMEOUT_MS`）；耗尽 → `inconclusive(model, budget_exhausted)`。
- **提交校验**（服务端，任一不满足即拒绝该工具调用并给出可纠正错误）：
  - `step_record.seq` 必须是当前下一个未完成步骤；不允许跳步/回退/重复。
  - `step_record.status` 只允许 `passed|failed`；`failed` 必须有 `actual`/reason。
  - `assertion_record.assertion_id` 必须属于本用例快照；同一断言只能提交一次；`passed/failed` 必须带至少 1 条本用例证据 ID。
  - `case_finish` 只有在全部步骤已记录且所有非 db 断言已提交后才允许；verdict/class 组合必须符合 §5.8；`passed` 额外要求证据齐备。
  - 未记录的步骤/断言 → 不允许 `case_finish(passed)`。
- 工具错误统一映射为 `ToolError{Code,Message}`：`invalid_arguments|denied|not_found|timeout|cancelled|internal|host_not_allowed|session_unauthorized|executor_unavailable|target_not_found|target_ambiguous|paused`。
- 恢复运行：新 Agent run 的 system/user 消息包含「已完成步骤（含 actual/证据数）+ 剩余步骤 + 是否 cleanup_required」；cleanup 动作仍用浏览器/HTTP 工具完成（P6 无夹具 API）。
- 模型/网关失败 → `inconclusive(model)`；不重试无限循环（每用例最多一次自动会话重取，不自动重跑模型）。

### 5.6 执行器协议（A′）

- 传输：HTTP/JSON，`Authorization: Bearer <EZTEST_EXECUTOR_TOKEN>`；仅绑 `127.0.0.1`（容器内网），默认端口 13336。
- `POST /v1/contexts`：

```json
{"key":"case_run:1841...", "allowedHosts":["127.0.0.1","localhost"],
 "baseUrl":"http://127.0.0.1:13335",
 "storageState":{"cookies":[...],"origins":[{"origin":"...","localStorage":[...],"sessionStorage":[...]}]},
 "viewport":{"width":1440,"height":900}}
→ {"contextId":"ctx_1","browserVersion":"..."}
```

- `POST /v1/contexts/{id}/actions`：`{"action":"goto","args":{...}}` → `{"ok":true,"result":{...},"artifacts":[{"kind":"screenshot","mime":"image/png","base64":"...","sha256":"..."}]}`；失败 `{"ok":false,"error":{"code":"target_not_found","message":"..."}}`。
- 动作与参数：

| action | args | result |
|---|---|---|
| `goto` | `url, wait_until?, timeout_ms?` | `url,status` |
| `snapshot` | `max_chars?`（默认 12000） | `url,title,aria`（ARIA YAML，只读，不含密码值） |
| `click` | `target,button?,click_count?` | `ok` |
| `fill` | `target,value,secret?` | `ok`；`secret=true` 的值不进日志/证据 |
| `press` | `key,target?` | `ok` |
| `wait_for` | `target?|text?|url_contains?,state?,timeout_ms?` | `ok` |
| `screenshot` | `full_page?,target?` | artifact `image/png` |
| `console` | `tail?`（默认 50，≤200） | `items[{type,text,ts}]` |
| `network` | `tail?` | `items[{method,url,status,duration_ms,mime}]` |
| `download` | `target,timeout_ms?` | artifact `application/octet-stream` + `filename` |
| `storage_state` | `include_session_storage?` | `{cookies,origins[{origin,localStorage,sessionStorage}]}` |
| `close` | — | `ok` |

- `target` 结构：`{"role":"button","name":"登录","exact":true}` | `{"text":"..."}` | `{"test_id":"..."}` | `{"selector":"..."}`；解析优先级按对象中出现的键，多键同时出现 → `invalid_arguments`；0 个匹配 → `target_not_found`；>1 且动作需单元素 → `target_ambiguous`。
- 上下文与 page：每 context 单 page；`acceptDownloads=true`；console/network 以 500 条环形缓冲采集。
- 超时：动作默认 15s、上限 60s；`goto` 默认 30s；每动作独立 AbortController；`cancel` 终止在飞动作并返回 `canceled`。
- 上限：`EZTEST_EXECUTOR_MAX_CONTEXTS` 默认 8；单次 artifact ≤10MB；动作请求体 ≤1MB；快照 ≤12KB 自动截断并标记 `truncated=true`。
- 安全：所有 http(s) 请求（含重定向/子资源）经 `context.route` 校验 host ∈ allowedHosts 或 = baseUrl host，否则 abort + `host_not_allowed`；禁止 `file://`；不提供任意文件读取/写入；临时下载文件写入 executor 临时目录并在 close 时清理。
- 健康：`GET /healthz` → `{status:"ok",version,contexts,maxContexts}`；API 启动/建批/运行中定期探测。

### 5.7 证据规则

- 自动取证：`browser.screenshot`、`browser.download`、`http.request` 每次调用生成 evidence（含 `evidence_ref` 指向 case_run；断言通过后追加 assertion_result 引用）；`console`/`network` 可带 `capture_evidence=true`。
- 文件路径：`{batch_id}/{case_run_id}/{evidence_id}.{ext}`；由 Go 生成；`filestore.Store`（D30 模式）负责根内校验/原子写/权限。
- 大小/数量：单证据 ≤ `EZTEST_EXEC_EVIDENCE_MAX_BYTES`（默认 10MB）；单用例 ≤ 100 条；超限返回错误，不静默截断（HTTP 响应体可截断但保留 `truncated=true` 与完整字节哈希语义：哈希针对保存的字节）。
- 不可变：无更新/删除 API；`updated_at` 不更新；删除仅 P8 GC。
- **脱敏**：HTTP 证据保存前对 `Authorization`/`Cookie`/`Set-Cookie`/`X-Api-Key` 等敏感头值打码（保留头名）；请求/响应体中的 `password/token/secret/apikey` 字段按 JSON 键名打码；`fill(secret=true)` 的值不产生证据、不写 console/network 日志。
- 读取：`GET /api/versions/{id}/evidence/{evidenceId}` 校验归属、sha256、MIME；`X-Content-SHA256`；不得暴露文件系统路径。
- 事件只带 `evidence_id`；报告/前端按需拉取。

### 5.8 四态判定与失败分类 v1

| 终态 | 允许 failure_class | 判定 |
|---|---|---|
| `passed` | — | 全部步骤 passed、全部非 db 断言 passed、断言/步骤证据齐备、无引擎级错误 |
| `failed` | `application` | ≥1 条断言 failed，且目标系统有正常响应、失败断言带证据 |
| `blocked` | `environment` / `session` | DNS/连接/超时/白名单/环境不可达；401/登录重定向/会话失效且重取一次仍失败；executor 不可用 |
| `inconclusive` | `model` / `case` | LLM/网关/工具内部错误、预算耗尽、证据缺失、用例结构不可执行（含 db 断言）、agent 输出非法 |
| `skipped` | — | 取消/未派发/批次终止 |
| `interrupted` | — | 立即暂停/崩溃 |

- 分类输入：工具错误码（`host_not_allowed`→environment、`session_unauthorized`→session、`executor_unavailable`→environment、`timeout`→按 URL/目标判断 env/application、`target_not_found`→默认 application（元素消失多为应用变更），`internal`→model）、Agent 提议、证据存在性。
- Agent 的 `failure_class` 只作提议；服务端覆盖时写 `classification_overridden=true` 到事件 detail 与 `failure_reason` 前缀，保持可审计。
- `db` 断言：P6 不支持（P7 实现只读 DB 断言）。用例含 db 断言 → 该断言 `not_run`，最终 `inconclusive(case, unsupported_assertion_kind)`；绝不假通过。
- **Flaky**：同一用例先前 attempt `failed(application)`、后续 attempt `passed` → 批次/报告标记 flaky（派生展示，不写入 `case_run.failure_class`，不改历史行）；P6 不自动重跑应用失败，提供手动 `rerun`。
- 自动重试仅限：同一用例 run 内 Session 失效重取一次；不做用例级自动重跑。
- 预算耗尽/上下文溢出 → `inconclusive(model)`，不判 failed（蓝图：预算耗尽 = 未完成）。
- 无证据的 passed/failed 一律降级：断言 `not_run`；用例 `inconclusive(evidence_missing)`。

### 5.9 Session 选择 / 自动登录 / 注入 / 失效重取 / 接管

- **选择**：见 §5.3；`SessionRef` 含 `sessionId`、`snapshotId`、`storageStateKind`（`storage_state`/`token`）、`storageState`、`sessionStorage`、`headers`、`expiresAt`。`storageStateKind=storage_state` 时把 `storageState`/`sessionStorage` 注入浏览器 context；`token`（含 apikey/basic）只把 `headers` 注入 `http.request`，不建浏览器 context。
- **自动登录资格**：`access.enabled`、`auth_type='password'`、credential 非空、`env.allow_auto_login=true`、`login_flow_id` 指向启用的 form 配方、环境可达；`env.is_prod && require_approval` → 直接 `needs_manual(approval)`。
- **流程**（resource.application，单飞键 `(account,system,environment)`）：
  1. 创建/复用 session 行 `pending→acquiring`；
  2. 调 `LoginBrowser.Run`：执行器建 login context → `goto(login_url)` → `fill(username)` → `fill(password, secret=true)` → `click(submit)` → `wait_for(success)`；
  3. 成功 → `storage_state`（含 sessionStorage）→ 写 session（`state=valid, acquisition=auto`，`expires_at` 按 cookie/`session_ttl_seconds`）→ `login_check`（若配置）复核 → `session_snapshot`；
  4. `failure.mfa_selector`/`captcha_selector` 命中 → `needs_manual` + 创建 waiting takeover（reason=mfa/captcha）→ `PendingTakeover`；
  5. `invalid_selector`/提交失败 → `failed`（reason=credential_invalid/login_failed）；
  6. 超时/环境不可达 → `failed`（env_unreachable）；
  7. 完成 → 重新选会话并租约；`needs_manual` → 用例 `blocked(session)`。
- **注入**：storageState 直接作为 Playwright context 初始状态；`sessionStorage` 经 init script 注入；token/apikey/basic 会话仅用于 `http.request` 头注入，不建浏览器 context。
- **失效重取**：工具返回 `session_unauthorized` 或导航落到登录页 → `MarkSessionInvalid` → 同一用例内重取一次（自动登录或换有效会话）→ 重试当前动作；再次失败 → `blocked(session)`；不记应用缺陷。
- **接管（表单 A）**：等待期间释放租约；管理员通过既有 `POST /api/resources/takeovers/{id}/complete` 上传 storageState → 会话 `valid`；worker（2s）发现该 CaseRun 仍 `blocked(session)` 且会话有效 → 自动重排为**新 attempt**（`retry_of_case_run_id`，不计失败预算），并继续批次。
- **安全**：密码/凭据不入事件、日志、证据、快照、前端；`fill(secret=true)` 的值在 executor 内不记日志；错误消息不含 credential。**执行 Agent 不接收任何凭据**：登录由会话注入完成；`case_context` 对 `test_data/preconditions` 中键名匹配 `password/passwd/token/secret/apikey` 的值打码为 `"***"`。
- **无会话可接管例外**：若根本没有 Session 行（auth_type=manual / 未配置配方），只能 `blocked(session, no_session)` 并提示管理员导入或配置；接管卡只在 MFA/验证码/审批产生 waiting takeover 时出现。
- P6 不做权限探测配方；仅在配置了 `login_check` 时做一次登录校验。

### 5.10 事件与实时

- 通道 `version:{id}`；事件类型（OpenAPI `VersionEventType` 追加）：
  `batch.created`、`batch.started`、`batch.paused`、`batch.resumed`、`batch.finished`、`run.started`、`run.paused`、`run.resumed`、`run.finished`、`step.started`、`step.finished`、`evidence.created`、`case.status_changed`、`human.requested`、`gate.pending`、`gate.resolved`。
- 字段沿用 P0 信封：`seq,type,version_id,batch_id,case_id,step_id,agent_role,session_id,ts,summary,detail,refs`；`summary ≤500 rune`、`detail ≤64KiB`、`refs ≤20`。
- `agent.activity` 通过 `activity_channel=version:{id}` 进入同一通道（Sessions Tab 消费）。
- `human.requested`/`gate.pending` 携带 `takeover_id/session_id/reason`；`gate.resolved` 在接管完成/取消时发。
- 事件不放脑图正文、LLM 原文、凭据、证据正文；证据只放 ID。
- 写-后-发：DB 事务提交后才发布；失败补偿不发"成功"事件。

### 5.11 权限与审计

- 建批/暂停/恢复/取消/重跑：所有登录用户（与 P3 版本域写权限一致）。
- 证据读取：所有登录用户（版本数据只读权限）。
- 登录配方 CRUD、Session 导入/校验/接管完成：管理员（沿用 P2）。
- 执行器 token 仅 API 进程持有。
- 审计：`execution.batch.created/paused/resumed/cancelled`、`execution.case.finished`（只记 id/状态/分类/耗时，不含凭据与 prompt）。取消批次写 `execution.batch.cancelled`；暂停/恢复分别写 `execution.batch.paused`/`execution.batch.resumed`（同一 `BatchPaused` 适配按 `paused` 布尔分流）。工具调用审计沿用 P1（不含参数/结果）。

### 5.12 核心不变量（测试锚点，逐条必须有测试）

1. 单版本最多 1 个活跃批次；暂停不释放活跃位；批次必须绑定一致基线哈希。
2. `case_snapshot` 批次内不可变；脑图行被外部改动不影响本批执行（哈希校验只发生在建批）。
3. 证据只写不改；读取校验 sha256；`passed/failed` 断言必须有证据，否则 `not_run`。
4. `paused` 独立于 status；优雅暂停不产生 `interrupted` 用例；立即暂停必定产生 `interrupted` 且记录步骤号。
5. 恢复从最后完成步骤续跑，不重跑已完成步骤；interrupted 恢复前必须 cleanup/seed。
6. 失败分类与终态组合受服务端校验；应用缺陷只来自有证据的断言失败。
7. 重启后 running→interrupted、批次 paused(restart)、租约释放，且不自动拉起浏览器。
8. `db` 断言永不产生 passed；预算耗尽永不产生 failed。
9. 所有执行 ID 在 JSON/URL/事件/工具参数为十进制字符串；证据/凭据内容不入事件。
10. 取消后 pending→skipped、running→interrupted，批次 cancelled，版本保持 executing。

## 6. API

### 6.1 约定

- 成功 `{"data": ...}`；错误 `{"error":{"code","message","request_id","retryable","details"}}`；列表 `next_cursor/has_more`。
- 创建/控制类支持 `Idempotency-Key`；幂等窗口沿用 P0。

## 7. Agent 与提示词

### 7.1 `execution-agent` profile（seed，`Builtin=false`，幂等）

| 字段 | 值 |
|---|---|
| key | `execution-agent` |
| name | 执行 Agent |
| allowed_tools | `execution.case_context`、`browser.goto/snapshot/click/fill/press/wait_for/screenshot/console/network/download`、`http.request`、`execution.step_record`、`execution.assertion_record`、`execution.case_finish` |
| max_turns | 30（1–100） |
| run_seconds | 900（60–3600） |
| hard_timeout_seconds | 120 |
| max_output_tokens | 8192 |
| thinking | 可配（默认 false） |

- 启动时对活注册表校验每个工具存在；缺失则 fatal，不 seed。
- 管理员可在 P2/P1 既有 profile 面修改提示词/模型（P6 不新增配置面）。

### 7.2 系统提示词要点（写入 `execution/domain/profile.go` 常量）

1. 你是执行 Agent，只执行给定用例快照，不修改用例、不新增断言、不越出环境白名单。
2. 严格按步骤顺序：执行 → 用 `step_record` 记录该步骤结果 → 有断言则用 `assertion_record` 记录（必须带证据）。
3. 任何 passed/failed 断言都必须先产生证据（截图/HTTP 交换）；无证据就如实报 inconclusive。
4. 失败分类：只有目标系统正常响应且断言不符才算 `application`；连不上/白名单/超时算 `environment`；401/登录跳转算 `session`；模型/工具/预算问题算 `model`；用例本身不可执行算 `case`。
5. 禁止伪造、禁止跳过步骤；无法完成时 `case_finish(blocked|inconclusive)` 并说明原因。
6. 恢复运行：先看已完成步骤，不要重跑；`cleanup_required=true` 时先用浏览器/HTTP 做 cleanup/seed，再继续剩余步骤。
7. 所有 URL 必须是环境 baseUrl 或其 allowed_hosts 内；不要尝试访问其他主机。
8. 你不持有、也不要索取任何账号密码/凭据；登录态由系统注入。用例数据中的敏感字段已打码，输入密码类步骤应视为不可执行并报告 `case` 问题。

### 7.3 run 协调与降级

- 启动失败（LLM 未配置、profile 禁用、执行器不可用）→ 用例 `inconclusive(model|environment)`，批次继续。
- Agent run 的 `agent_run_id` 与 `agent_session_id` 落 CaseRun，供 UI 深链 transcript。
- 工具调用与活动事件沿用 P1（32KB 截断/2KB 预览）；截图只以 evidence id 出现在工具结果 JSON 中。
- 暂停/取消通过 `CancelRun(sessionID)` 与 executor cancel 双通道执行。

## 8. 执行器实现规格

### 8.1 目录与依赖

```text
executor/
  package.json        "type":"module", deps: playwright@1.64.1
  pnpm-lock.yaml
  src/server.mjs      HTTP server + token auth + health
  src/contexts.mjs    Browser/context 生命周期 + 并发上限
  src/actions.mjs     动作实现
  src/snapshot.mjs    ARIA 快照 + 截断
  src/security.mjs    allowedHosts 校验 + 大小限制
  test/*.test.mjs     node:test
  Dockerfile          FROM mcr.microsoft.com/playwright:v1.64.1-noble
```

- 版本钉死 `playwright@1.64.1`（与本机已装 Chromium 对齐）；容器用官方镜像，`PLAYWRIGHT_BROWSERS_PATH` 默认。
- 启动参数：`EZTEST_EXECUTOR_ADDR`（默认 `127.0.0.1:13336`）、`EZTEST_EXECUTOR_TOKEN`（必填）、`EZTEST_EXECUTOR_MAX_CONTEXTS`（默认 8）。
- 健康检查与优雅关闭：关闭时关闭全部 context/browser。

### 8.2 动作实现要点

- `goto`：`page.goto(url,{waitUntil,timeout})`；非 2xx/3xx 不直接判失败（由断言决定），但在结果中返回 status。
- `snapshot`：`page.locator('body').ariaSnapshot()`（Playwright ≥1.49）；输出 YAML；剥离 `textbox` 的值中的密码（`type=password` 不输出 value）；截断并 `truncated`。
- `click/fill/press`：target 解析 → `waitFor({state:'visible'})` → 动作；`fill` 先 `click`；`secret=true` 时值不写日志/不返回。
- `wait_for`：`target`/`text`/`url_contains` 任一满足；超时 `timeout`。
- `screenshot`：`page.screenshot({fullPage,type:'png'})`；返回 base64 + sha256（executor 算，Go 复核）。
- `console`/`network`：页面创建时挂监听，环形 500；`network` 记录 `requestfinished` 与 `requestfailed`。
- `download`：`page.waitForEvent('download')` + `saveAs(tmp)`；读字节返回 artifact；清理临时文件。
- `storage_state`：`context.storageState()` + 对每个 origin `page.evaluate` 采集 sessionStorage；合并输出。
- 错误映射：Playwright `TimeoutError` → `timeout`；locator 解析 0/多 → `target_not_found/target_ambiguous`；`net::ERR_NAME_NOT_RESOLVED` → `dns_failed`；`ERR_CONNECTION_*` → `connection_failed`；路由 abort → `host_not_allowed`；其他 → `internal`。

### 8.3 安全与资源

- token 校验失败 401；请求体 >1MB 413；未知 action 400。
- 路由拦截：`context.route('**/*', handler)`，对 `http/https` 校验 host；`data:text/html` 仅供执行器自测（无网络）；其余 scheme abort；Go 侧执行工具只接受 http(s) URL。
- 单 context 并发动作串行（队列）；context 上限拒绝 `context_limit`。
- 下载/截图大小超限 → `too_large` 错误（HTTP 413/422）。
- 不在日志中打印 token、fill 值、storageState。

### 8.4 部署

- `deploy/docker-compose.yml` 增 `executor` 服务：`build: ../executor`，`shm_size: 1gb`，`EZTEST_EXECUTOR_TOKEN` 注入，健康检查，仅内网暴露；API 增 `EZTEST_EXECUTOR_URL=http://executor:13336`。
- `deploy/Dockerfile.api` 不变（Alpine）；API 不依赖 Node。
- 开发：`scripts/dev-executor.ps1`（`cd executor; pnpm install; pnpm start`）；`scripts/dev-api.ps1` 增加 executor 健康提示（不自动启动，保持职责单一）。
- `scripts/e2e.ps1`/`scripts/acceptance.ps1` 负责拉起/回收 executor。

## 11. 风险与降级

| 风险 | 处理 |
|---|---|
| 执行器不可用/崩溃 | 建批 503；运行中健康检查失败 → 批次暂停（reason），在飞用例 blocked(environment)；不误判应用缺陷 |
| LLM 不可用/超预算 | 用例 inconclusive(model)，批次继续；UI 降级提示 |
| Session 登录失败/MFA | 凭据/环境失败 → blocked(session,no_session/credential_invalid) 并提示修正；MFA/验证码/审批 → blocked(session) + 接管卡；均不记应用缺陷；接管后自动继续 |
| 进程/浏览器崩溃 | 启动恢复：running→interrupted、批次 paused(restart)、释放租约/context；用户恢复 |
| 白名单/环境错配 | blocked(environment, host_not_allowed) + 配置提示 |
| flaky | 分类 + 手动重跑 + 派生 flaky；不自动重跑应用失败 |
| 证据过大/过多 | 明确上限与错误；报告显示证据计数 |
| 执行不稳定 | 先 fixture 稳定目标跑通；超时/预算显式；宁严勿松 |
| 单实例调度 | P6 单进程；多实例需分布式租约（P8） |
| 执行器依赖版本漂移 | 钉 1.64.1 + lockfile + 官方镜像；健康返回版本 |

**降级路径**：执行器不可用 → 只读查看历史结果/证据/报告，禁止建批；LLM 不可用 → 执行仍可启动但用例 inconclusive(model)，允许人工重跑；Session 不可用 → blocked + 人工接管。
